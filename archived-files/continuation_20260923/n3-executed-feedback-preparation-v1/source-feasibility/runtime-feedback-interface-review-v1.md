# Runtime executed-prefix feedback — source-only feasibility

This review makes no candidate edit or new scientific read. It checks source525506ca for a deployment route matching the already frozen diagnostic's **actual pre-reset `robot0_eef_pos`**, rather than replacing it with the adapter's controller-origin `O`. A small execution-feedback interface is feasible using already returned observations; the current QD path does not yet receive or validate that interface.

## Exact observation route

`core/env_adapters/libero_adapter.py:807–843` receives `raw_obs` from the existing environment step. `_format_raw_obs` at742–786 places `raw_obs['robot0_eef_pos']` into `observation[f'{OBS_STR}.robot_state']['eef']['pos']`. `_convert_nested_dict` at146–165 uses `torch.from_numpy`, optionally adds the batch dimension, and **does not cast the source dtype**. The same raw array is passed to the passive collector's `pre_reset_outcome` at835/840, before automatic reset. The formatted step observation is returned at843.

The outer adapter at1695–1728 returns that observation after caching it in `_last_obs`. `main.py:2066–2071` already receives `obs, reward, terminated, truncated, info = self.adapter.step(...)`. A future opt-in policy callback at this boundary can copy exactly the returned raw-derived nested EEF tensor before later preprocessing or another step. This route needs no new environment query, render, policy observation pass, model/provider/projector call, or observer-file read. It can operate with the collector disabled. Copy immediately: the formatted tensor originates from a NumPy array view, so retaining a live reference rather than a snapshot would be unsafe.

The inner wrapper constructs the formatted observation **before** its automatic reset and ignores the reset return value; thus its returned tensor is the pre-reset observation by source flow. A future callback must still clear state and refuse promotion of feedback whenever `terminated` or `truncated` is true, regardless of whether8 actions were executed. No terminal feedback crosses reset. This avoids relying on post-reset alias lifetime, success labels, or a later observation getter.

Do **not** use `get_ee_pose_world()` as a substitute. That path (`:1147–1172`) returns `controller.ee_pos`, which is the projected-origin source. The diagnostic deliberately keeps source `O`, cast `x0`, actual post-action `p_i`, and the optional origin bridge distinct. The fact that both APIs describe EEF position does not make their values, update times or dtype interchangeable.

Do **not** recover `p8` from `_get_policy_observation`/a concatenated state tensor: adapter `get_policy_observation` at1083–1126 runs a processor, and the local fallback explicitly concatenates and casts state toFP32 at87–97. Imported processor behavior is another dependency. The earliest returned nested EEF avoids that transformation. Also do **not** call adapter `_get_raw_obs` at1137–1145: despite its name, that helper calls a simulator step with a dummy action, which would violate the fixed execution/cost contract.

## Required bookkeeping before an algorithm freeze

The existing source gives the required scheduling information without changing Stage: `main.py` already has episode, `global_steps`, `action_executed`, resolved horizon, `current_stage`, `use_guidance` and current provider list. At2074–2095 the loop advances the execution counter, gets the next policy observation and increments the global step; feedback should identify the just-returned action before those counters advance. At1780 it begins the fresh decision before selecting a chunk. A minimal new callback could carry `(decision-token, global-step, execution-index, copied-post-action-EEF, terminated, truncated)` into a dedicated internal-quality state. This is a proposed interface description, not an implemented API.

| Boundary | Required behavior |
|---|---|
| Fresh guided selection | Retain the actual selected candidate's already-computed full projection, uncast sourceO, native x0, semantic provider/target contract and execution start token; do not retain an arbitrary last-scored candidate. No extra projection. |
| Each successful returned step | Accept only the expected nextglobal/index for that decision; copy finite shape(1,3) or explicitly unbatched(3,) native EEF. No counter advancement on a missing result. Preserve known shape/dtype and cast only under the new explicit quality contract. |
| End of a full prefix | Only exactly8 consecutively acknowledged actions of a committed8-action chunk produce `p8`. Pair it with that same selected plan's `x8/x0/O`. For diagnostic-equivalent feedback the residual is `(p8−O)−(x8−x0)`, not `O_next−x8` and not an unnormalized absolute residual. Native storage/cast details require prospective tests. |
| Current decision using history | Previous full prefix must be complete before current selection, and its lastglobal+1 must equal the new start. No future/current-prefix outcome may affect the current choice. |
| OFF or a gap | Clear on every fresh unguided boundary; do not carry through OFF periods, missing steps or reactivation. Previously guided feedback cannot extend when QD runs. |
| Episode/reset/terminal/partial | `policy.reset` is called by main at1452 and already clears existing memory; new dedicated feedback must clear there too. | Registry/target change | The tracked target index must come from the proven generic provider expression, never a default0. Compare an explicit registry generation/registration identity and target semantic identity; registry replacement/reset invalidates even if index and current coordinates happen to match. This bookkeeping can be separate from existing `_eds_chunk_memory`; blindly enabling the historical memory feature would introduce a second mechanism. Keep Stage/provider/input/action definitions and baseline behavior unchanged when the new mode is off. Pass no task-ID/seed/success/path branch into the quality rule. The actual selected candidate's original raw scalar must still survive archive replacement/selection and drive the unchanged Stage normalization.

## Concrete gap: target registry validity

`core/keypoint_tracker.py:62–84` registers keypoints by replacing `_keypoint_registry`, and `reset` at206–209 replaces it again. A registration generation token can therefore be exposed from existing operations without another pose/perception query; object names must not select a rule. Runtime object identity/registration must be compared without using changing world coordinates as a hash key.

However, `get_keypoint_positions` at158–180 can return an initial position when its existing object-pose lookup fails. Its present return type exposes positions only: it has no per-call fallback/validity flag. An unchanged registry or valid numeric position is **not** proof that target tracking stayed valid. Before claiming fail-safe invalidation, choose and freeze one of: a passive validity token produced by the already-executed tracker call without changing its output/query count, or conservative Unknown/fallback that declines to carry feedback when validity cannot be established. This is a real interface gap; it cannot be solved by reading the observer or treating unchanged provider hashes as physical target continuity. Any new metadata plumbing needs tests that it leaves the perception/Stage computation and call counts unchanged.

## Conclusion and limits

Exact past `p8` is available through the already returned native observation; no simulator callback or controller-origin approximation is necessary. A small observation-to-quality feedback interface, exact selected-plan provenance and explicit lifecycle state are still required. The current implementation does not already establish those contracts. Source feasibility does not prove residual causality, general predictivity, task benefit, target validity, or historical controller clipping. No candidate has been implemented or frozen by this review.

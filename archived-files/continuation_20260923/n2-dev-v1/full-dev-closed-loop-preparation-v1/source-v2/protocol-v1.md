## Optional chronology and boundary clarifications

- A producer may create `stage_events.jsonl` only on its first event. Declare an absent optional source explicitly as `status=not_recorded,path=<exact standard path>` and verify the path is absent. Output event list, query counters and event associations as `null`, with status `not_recorded`; **never synthesize an empty stream or zero queries**. A present empty SHA-bound file is a recorded empty stream and differs from absence. An undeclared/unexpected/mismatched file is an integrity error. Absence does not invalidate an accepted task success or prevent the actual-action chronology from completing.
- Keep every allowlisted Stage event, including unchanged state, skipped/error status and unknown/multiple associations. Same-step actual decision state and recorded query after-state are compared, never overwritten. First/last sent gripper values come from a unique same-reset executed prefix ending one step earlier, not from assumed full8 chunks. No predecessor, initial step or reset makes that comparison Unknown. Exact comparisons are descriptive, not new trigger predicates; all logged gripper fields remain separate.
- Per-cell guidance coverage counts actual linked actions, including successes shorter than720 or a partial last chunk. First OFF is `step=null,status=not_observed` when absent; initial OFF is separately recorded. No missing transition becomes step0. All reactivations and all runs survive. Unsupported-provider fallback applicability/reasons are copied only from the authoritative matrix records and are not an exclusion or a new Q8 requirement.
- EEF summaries use the existing helper's arithmetic. A contiguous preceding post-action observation is an EEF origin when available; otherwise the first post-action observation is the origin and the first-action displacement is unobserved. No edge crosses a gap, terminal/truncation or reset. Finger qpos begins at the run's first post-action measurement; command-sign counts exclude its starting boundary. These different origins are explicitly stored. No projected initial EEF or returned reset observation is substituted.
- Native tensor dtype/shape is preserved. JSON/Python-float arithmetic does not improve BF16/FP32 source precision. Gripper command sign/finger coordinates do not identify grasp or contact. Missing finger fields remain nullable. Motion components are not target progress or independent trials.
- A zero-action decision can be represented safely by the pure reducer as zero coverage/no motion, but the **unchanged frozen auditor rejects an unexecuted decision** in a complete admitted episode. This implementation does not relax that existing gate to make such a real artifact pass.

## Read and write behavior

The only imported analysis capabilities are the frozen task0 helper's pure extraction/motion/identity functions and the unchanged CPU `audit_episode`. Its task0-specific `run`, old authorization, formatting scripts, selected-quality and keypoint/projection helpers are not called. The auditor may examine stored scoring arrays for its existing completeness check; that is not a new score/model/provider call. The auditor loads one whole episode in CPU memory; extraction thereafter streams bundles and retains only decision/action/reset observations. There is no promise of single-bundle peak memory during the existing audit.

Every admitted index/bundle SHA is verified before the fresh audit and again on extraction. Tensor loading is CPU with `weights_only=True`. All source/input hashes and declared absences are rechecked before final success. Extra unindexed bundles are rejected by the frozen auditor. No credentials, images/video, log/Stage-response prose, target labels/maps, invalid episode contents, external session results, validation/formal artifacts, simulator or model/provider/projector call is permitted.

Write only a new directory under `A/continuation_20260923/full-dev-closed-loop-analysis/`: each cell's chronology and fresh audit, full30 index, overview, provenance, and explicit analysis status. All cells remain in frozen task/arm order regardless of manifest order; old outputs are never overwritten. If extraction fails, preserve prior partial output and `status.complete=false`; do not drop a cell or amend original outcomes. All actual run outputs must wait for a new root authorization after all30 accepted representatives exist.

Analysis `complete=true` means every authorized representative and available allowed source was processed; it does not make optional unrecorded Stage fields or the explicitly Unknown scientific quantities known. Missing optional Stage data remains visible per cell even in a complete descriptive output.

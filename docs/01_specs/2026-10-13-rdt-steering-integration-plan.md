**RDT Steering 整合方案（审阅稿，2026-10-13）**

目标是在共同的 RDT 推理框架中提供 VLS、EDS、EDS+QD 三种可切换的 steering 方法，先保住已验证的 EDS 性能，再建立公平对照，最后支持团队共同开发更有效的 QD 机制。

本稿取代此前整合方案的实施顺序与公共命名约定，迁移范围、接口、验证与协作安排均在本文中独立说明。当前仅形成方案，尚未执行代码迁移、合并或新实验。历史证据保持原样。

**一、交付目标与命名约定**

| 展示名称 | 公共配置标识 | 定位 |
| --- | --- | --- |
| RDT + VLS | `vls` | reward 梯度、RBF 排斥和 FKD 的比较方法 |
| RDT + EDS | `eds` | 带 RBF 的候选演化搜索；首先迁移、验证和冻结的性能基线 |
| RDT + EDS+QD | `eds_qd` | 在 EDS 搜索中加入行为档案、精英维护和父代分配的研究方法 |

公共代码、配置、命令、日志、图表、测试名称均使用算法或职责名称。运行编号、时间戳及内容哈希仍用于区分实验，但不成为算法名。无引导 RDT 保留为辅助控制组，不计入三种 steering。

具体来源分支、整合分支、工作树、提交与历史名称的对应关系，在整合完成后的 README 追溯部分集中记录。运行所需配置不得依赖这些名称或机器上的研究目录。冻结的历史源码与原始结果不批量改名，保证证据哈希与原始记录可核验。

最终交付应包括：

- 一个可复现的 EDS 配置及对应验收结果。
- 三种 steering 共用的运行与评测入口。
- 一套明确的 Stage、reward、初始化和结果审计协议。
- VLS、EDS、EDS+QD 在同一协议下的首轮完整结果。
- 可供合作者安装、运行、定位模块和继续研究的 README。

**二、算法结构与本次边界**

三种用户模式对应两条底层推理路径；EDS+QD 复用 EDS 的加噪、短去噪、RBF 与评分过程，不复制第三套策略推理代码。

```text
观测、语言、机器人状态
          ↓
共享 RDT 权重与输入适配
          ↓
共享 Stage 控制、reward 合同与引导开关
          ↓
steering.method
   ├─ vls    → 梯度引导 + RBF + FKD
   ├─ eds    → 评分重采样 + 加噪/短去噪 + RBF
   └─ eds_qd → EDS + 行为档案 + 档案父代/最终选择
          ↓
共享动作解码 → 执行动作块 → 新观测
          ↓
共享任务计分、日志与机制审计
```

当前参考机制的区别如下：

| 机制 | VLS | EDS | EDS+QD |
| --- | --- | --- | --- |
| reward 的作用 | 梯度引导并参与采样/选优 | 候选评分、父代重采样与最终选优 | 候选质量、档案精英更新与最终选优 |
| RBF | 有 | 有 | 与 EDS 保持相同 |
| 父代/候选分配 | 沿用现有 VLS/FKD 实现 | 当前群体的 reward 加权采样 | 从占用网格的精英分配父代 |
| 最终选择 | 当前候选中选优 | 默认最后一代中选优 | 当前动作块历代档案中选优 |
| 跨动作块 QD 记忆 | 无 | 无 | 当前参考实现无 |

EDS 的候选轨迹评分基于动作构造的位置投影，并非对每个候选执行环境仿真。现有 RBF 是逆距离形式的径向排斥；不能把它描述成高斯核实现。VLS 和 EDS 已有群体多样性机制，论文对照应区分“QD 与非 QD”，而不是“有多样性与无多样性”。

首次整合只迁移已有、可核验的行为，不同时引入新 reward、新描述符、跨块记忆或新的恢复策略。大型文件拆分与插件化重构也后置，先使用小范围适配建立稳定接口。

**三、实施顺序与阶段交付**

| 阶段 | 执行内容 | 交付与进入下一阶段的条件 | GPU / 在线调用 |
| --- | --- | --- | --- |
| 1. 冻结迁移依据 | 核对实际源码、配置、资产、环境与初始化证据 | 迁移清单、内容哈希、依赖清单、验收协议 | 无 |
| 2. 独立迁移 EDS | 迁移选定的已验收 EDS 所需完整闭包，清理机器路径和历史命名耦合 | CPU 与离线一致性检查通过；EDS 可独立运行 | 先无；检查通过后进行加载预检 |
| 3. 验收 EDS | 按已验证条件完整执行十任务 | 完整结果与差异分析；确认性能基线是否成立 | GPU2，10 回合，在线 Codex |
| 4. 接入三模式 | 统一入口、Stage/reward 外层接口与模式校验，接入 VLS 和 QD | 三路径机制检查；确认 EDS 行为保持一致 | 以 CPU/离线检查为主；有行为变化则重测 EDS |
| 5. 建立共同对照 | 在冻结的共同协议下评测三种模式 | 配置、逐任务结果、耗时及机制审计可比较 | VLS 10 回合、EDS+QD 10 回合；必要时 EDS 另 10 回合 |
| 6. 合入协作主线 | 完成评审、最小使用文档、可回退提交与 README 追溯 | 三模式可运行，EDS 状态明确，QD 研究边界清楚 | 不自动追加研究实验 |
| 7. 开展 QD 研究 | 从已冻结 EDS 对照出发迭代机制 | 有对照和消融支持的改进结论 | 后续研究安排 |

顺序的核心是：**先验证 EDS 搬迁，再统一接口，再做比较，最后在稳定主线上开展算法改进。** 阶段 4 的适配若改变 EDS 科学条件，阶段 3 的成绩不能直接充当阶段 5 的 EDS 对照。

整个整合过程使用现有工作区；不为此次整合另建工作树。实验输出继续在现有实验管理目录下按算法和运行编号分开存放。现有主工作区的未提交文件不覆盖，来源研究代码与证据保留。

**四、先迁移并验收 EDS**

**4.1 冻结什么**

迁移对象是经过核验的实际文件集合，不只是一条分支的已提交内容。已有关键实现包含未提交文件；迁移前逐项核对运行时源码、配置、提示词、测试、资产与启动依赖，记录内容哈希。

冻结的条件至少包括：

| 层面 | 要保持的条件 |
| --- | --- |
| 模型 | RDT checkpoint/EMA、文本与视觉编码器、动作归一化及调度器 |
| 输入输出 | 图像处理、历史观测、机器人状态映射、动作解码与夹爪语义 |
| 搜索 | EDS 参数、RBF、生成人口方式、重采样和最终选择规则 |
| 控制 | Stage 提示词、事实解析、完成判定、失败复查、引导开关与 reference 复位 |
| reward | 目标身份绑定、数值合同、输入切片、有效性校验与零分阶段语义 |
| 实验 | 十个任务、初始状态、完整 RNG 恢复点、步数与等待设置 |
| 服务 | 已验收的 Codex 模型、推理强度、调用与异常处理协议 |
| 依赖 | Python/核心库、RDT 与任务资产版本、模型文件及配置哈希 |

不能用“相同 seed”代替完整初始化一致性。保留准备与 rollout 两个阶段的 RNG 恢复点和执行顺序；预检不得污染正式运行的随机数状态。模型下载、环境检查与 API 探测尽量在独立进程中完成。

LIBERO 的任务定义、初始状态和 mesh 等属于必要实验资产，不能当作普通研究日志删除。模型权重通过可配置路径与哈希定位；编码器采用明确快照，不能按最近修改时间自动选取。

**4.2 EDS 的初始冻结设置**

以下是迁移要保留的已验证参数，不作为这一阶段的调参空间：

- 每次搜索 16 个候选，初始完整去噪 5 步，之后 10 轮演化；不开启 CEM。
- 初始 RBF 强度 20、比例 0.8；短去噪阶段 RBF 强度 20、比例 0.6。
- 短去噪步数为 `[3, 2, 2, 2, 2, 1, 1, 1, 1, 1]`；不额外添加无排斥的尾段。
- 父代权重沿用现有 `softmax(0.1 × reward)` 语义，不能因参数名含 temperature 就改成除以 0.1。
- 不启用 QD archive、精英携带、跨块 population memory；最终从最后一代选优。
- reward 保留目标距离的加权负平方形式与原有目标绑定；阶段切换与零 reward 的引导关闭保持一致。
- 动作块执行 8 步；任务编号 0–9，各 1 回合，原初始状态行、seed/RNG 及 720 步上限保持一致。
- 保留在线事实驱动的完成确认、失败接触复查和恢复引导机制；环境成功信号是最终任务计分依据。

RBF 的具体作用时刻、trajectory 切片、夹爪解码等以冻结配置和源码为准，不在迁移中凭概念描述重写。

**4.3 验收分为三层**

1. **完整性：**依赖闭包、配置、资产和初始化夹具均可定位；不再依赖另一个研究目录里的隐含文件。
2. **确定性行为：**固定输入/RNG 下，比较 reward、Stage 状态转移、门控、候选选择及动作输出；纯命名调整也必须通过这些检查。
3. **在线性能：**GPU2 完整执行十任务，每个任务重新生成身份/阶段与 reward 内容，并根据实际观测在线调用 Codex Stage；不得用缓存回复代替这组在线实验。

本次选定、已验收的在线 EDS 迁移参照为 **3/10**，限定于冻结的服务、控制与初始化协议，不表示对所有历史实验条件作全局排名。建议本次发布目标为达到至少 3/10。它不是在线模型重新调用后的确定性保证，也不足以单独证明总体成功概率。

若不足 3/10，先判断运行是否有效、冻结项是否漂移、差异首次出现在哪里。必要时对来源实现和整合实现做同条件配对诊断，结果另列。不得重复运行直到碰到 3/10、替换合法失败，或拼接多轮任务凑成一个十任务结果。若工程一致但在线性能未恢复，报告应明确“工程迁移通过、性能验收未通过”，先定位再推进性能发布。

**五、接入三模式及共用接口**

**5.1 一个公共入口，配置含义明确**

以下是拟新增的公共配置形式，不代表当前已有可运行命令：

```yaml
policy:
  type: rdt

steering:
  method: eds  # vls | eds | eds_qd
```

配置展开保留当前实现语义：

| 公共方法 | 内部 guidance 路由 | QD archive |
| --- | --- | --- |
| `vls` | `vls` | 关闭 |
| `eds` | `eds` | 关闭 |
| `eds_qd` | `eds` | `grid_archive` |

公共 selector 是唯一权威来源；兼容层接收旧配置时进行显式转换，冲突组合直接报错。不能把尚未实现的 `eds_qd` 当作现有底层枚举直接传入。

新增配置建议按职责组织：

```text
configs/steering/vls.yaml
configs/steering/eds.yaml
configs/steering/eds_qd.yaml
configs/evaluation/libero_object_swap.yaml
configs/stage/online.yaml
configs/reward/target_squared_distance.yaml
```

实际实施时可沿用现有配置框架和目录惯例；关键是算法参数、评测协议、机器路径、服务设置相互分离。新 RDT 入口默认推荐已验收的 EDS；不因此改写仓库其他策略的全局默认行为。

历史名称出现在可迁移函数、类、配置或测试中时，按真实职责改名，并同步 import、启动入口和测试引用。旧入口确需保留则集中于兼容层；公共路径不形成两套长期并行的命名体系。原始证据中的名称不回写。

**5.2 共用 Stage，但先统一它消费的信号**

VLS 与 EDS 当前传给外层的归一化 reward 来源不同。直接让同一 Stage 阈值消费不同含义的数值，会导致“同一控制器、不同门控语义”。

共同协议应明确：

- 搜索层返回最终所选动作、候选原始 reward、候选来源及统计。
- 外层按共同规则计算所选候选的阶段进展指标；阶段 reference 的建立和复位时机一致。
- VLS 内部梯度缩放所需的归一化单独保留，不与外层阶段进展混用。
- EDS 的适配先与已验收行为核对；任何数值、状态转移或调用顺序变化，都需要检查影响并按需重跑 EDS。
- reward 接口分别声明“可评分”和“可微分”能力：EDS/QD 需要有效分数，VLS 还需要有效梯度；不静默降级。
- 保留本轮已有的内部 trajectory 切片差异；如后续统一切片，视为明确的算法/协议改动并另测。

Stage 负责阶段与引导开关，steering 负责动作搜索。QD 不在本次整合中自行修改完成条件、失败恢复或终止逻辑。异常、缺失输出和非法格式必须可审计，不能默认为成功完成阶段。

**5.3 QD 的第一版参考配置**

沿用已实现的简单机制：目标相对的、执行前缀位置投影的终点 XY 描述符，4×4 网格，每格保留高 reward 候选；网格边界由初始群体建立，在当前动作块内固定。

首个参考配置固定一种已有父代策略，建议使用稀疏优先分配；均匀分配作为后续独立对照。其余 EDS 参数、RBF、种群与演化轮数一致。

必须核对描述符的目标身份与 reward 目标一致。档案在每个动作块重新建立；当前参考模式不启用跨块记忆。只记录档案统计的 observer 不等于启用 QD，日志必须区分二者。

QD 同时影响父代分配和最终候选选择范围，因此首轮结果是整个 EDS+QD 实现的系统效果，不能直接归因为行为多样性。

**六、测试任务、GPU 任务与验收矩阵**

**6.1 CPU 与离线任务**

这些任务不消耗正式十任务实验回合：

- 配置解析、模式路由、非法组合与 provider 隔离检查。
- reward 数值、目标绑定、梯度能力及 Stage/reference 门控一致性检查。
- 完成证据、失败接触、遮挡、无效回复、超时等状态机回归。
- QD 更新、父代来源、最终选择来源、动作块清空与随机数隔离检查。
- 必要的现有回归测试与小型离线夹具比较。

已有测试依赖大型研究目录时，提取有来源哈希的最小夹具，不能通过“文件不存在就跳过”制造通过结果。只添加覆盖真实契约或回归风险的测试，不为每个简单改名重复编写测试。

**6.2 GPU2 与在线服务任务**

| 顺序 | 实验 | 回合数 | 要回答的问题 |
| --- | --- | --- | --- |
| 首先 | EDS 迁移验收 | 10 | 选定的已验收 EDS 搬迁后是否保持行为与性能 |
| 条件触发 | 共同协议下的 EDS | 10 | 若统一接口改变科学条件，新对照是多少 |
| 随后 | 共同协议下的 VLS | 10 | 梯度 steering 在共同外层设置下表现如何 |
| 随后 | 共同协议下的 EDS+QD | 10 | 现有 QD 参考机制相对 EDS 有何变化 |

通常共 **30 个主回合**；若共同接口使 EDS 需要重新建立对照，则为 **40 个主回合**。诊断运行单独登记，不计作重复补齐或替换原结果。

GPU2 执行 RDT 推理、候选搜索、必要渲染与环境评测；Codex 在每回合生成身份/阶段和 reward 内容，并响应运行中的 Stage 请求。reward 函数生成并校验后，其候选数值评分在本机执行，不是每个候选都远程调用模型。

本轮只使用当前 Codex 接入，固定已验收模型和推理强度，不恢复其他 provider，也不静默切换服务。API 不可用时记录并定位基础设施问题；不能用回复回放伪装为在线结果。

固定缓存和旧回复只用于离线诊断。三模式的在线请求使用各自实际观测，因此回复和调用次数可以不同；共同的是生成协议和输入权限，不是强迫不同轨迹共用答案。

**6.3 什么必须相同，什么必须如实记录**

固定权重、输入处理、任务、初始化、执行长度、步数上限、Stage/reward 合同、服务设置与计分规则。EDS 和 EDS+QD 第一轮保持相同候选数、演化轮数和去噪日程。

VLS 与 EDS 的原生计算量不同：现有 VLS 为 20 粒子、5 步去噪；EDS 为 16 粒子、合计 21 次批量去噪调用。共同环境条件不等于相同计算量。首轮展示原生配置结果，同时记录实际模型前向、处理候选量、reward/梯度调用、API 调用、GPU/CPU 与端到端耗时。

后续论文比较再补充匹配计算量或性能—代价曲线；计算统计用于科学比较和排期，不设新的固定研究额度上限。

逐任务报告至少包含：有效性、成功/失败、环境步数、终止原因、Stage 切换、引导占比、完成/恢复判定、候选来源与耗时。视频与必要关键帧作为定性证据，环境成功信号作为定量计分依据。

**6.4 发布门槛**

- EDS：迁移完整、工程检查通过，在线性能验收状态明确；性能未恢复则先诊断。
- VLS：真实进入梯度路径，完成有效十任务评测，无静默降级。
- EDS+QD：真实启用 archive 和父代/最终选择，完成有效十任务评测，无禁用或空跑。
- 首轮 QD 不要求超过 EDS 才能作为研究实现合入；低分必须公开记录，不标成最优方法。
- 三模式的功能验收与“QD 已带来性能提升”的科学结论分别报告。

**八、合入后的 QD 优化顺序**

1. **先分离精英保留与多样性的贡献。**增加 EDS 的历代 best-so-far 最终选优、容量匹配的无分格 top-K 档案对照，再与 EDS+QD 比较。
2. **再优化行为描述符与质量。**检查 XY 终点覆盖是否对应真正有用的接近、抓持和搬运；新描述符与质量项分别做消融。
3. **再优化父代与探索分配。**比较均匀、稀疏优先和质量/不确定性相关分配，保持其他搜索开销可比。
4. **最后引入执行反馈。**研究真实执行后如何重评候选、调整可信度与下一块提议，并定义阶段变化时的失效和清理规则。

现有 QD 只在动作块内积累精英，不能直接称为已实现跨块或跨任务的递归自我改进。执行反馈与受控记忆作为后续独立功能；若使用仿真真值作控制输入，应单列额外信息条件。

固定十任务达到至少 5/10 是开发里程碑；正式论文结论还需要预先冻结协议、多 seed 和独立评测。若共用这些任务反复调参，应如实标记为开发集。

**九、预计工作量与审阅重点**

工程整理、接口和 CPU 检查可先按 1–2 个工作日估算，实际取决于依赖便携化与回归差异。在线评测按每十任务约 2–3 小时预留；30 回合约 6–9 小时，需重建 EDS 对照时约 8–12 小时。以上是排期估算，不是已启动状态、保证完成时间或任务硬超时。

本方案建议确认的核心边界是：以 EDS 性能保持为第一目标；三模式通过共享框架切换；公共名称只体现算法职责；首次合入交付可复现的研究起点，随后再以受控实验推进 EDS+QD 的性能与递归改进。

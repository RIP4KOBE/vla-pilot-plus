# N32 prospective production adapter

This is CPU-tested engineering code, not a release, adoption, GPU authorization,
or scientific result. `plan.draft.json` and its validator remain disabled.
No root artifacts are generated by this adapter. Root must review this commit,
adopt an actual committed checkout and budget, and supply the following objects.

## External release contract

The dependency order is inputs → plan → root review → detached release → worker
context → receipt/terminal. The plan contains no review or release reference, so
no self-referential hash is required. The official invocation requires both the
plan and release file paths **and externally supplied SHA256 digests**:

```
python -m scripts.qd_ed_n32_runner --plan <root-plan> --plan-sha256 <root-plan-hash> --release <root-release> --release-sha256 <root-release-hash>
```

These placeholders are documentation only. There is no release generator,
permissive fallback, authority template with fabricated hashes, or automatic
state amendment. Hash references establish integrity relative to the root's
out-of-band invocation; this code does not authenticate a human root signer.

`qd_ed_n32_release.validate_release` defines the prospective schemas:

- `n32-released-plan-v1`: frozen/release enabled, exact existing task-major
  C0/Q0/N32 rows and thirty external manifests, `attempt_identity: episode_key`,
  source record, runtime reference, protocol/authority references, and Dev-only
  phase authorization. It also carries the existing generic `run_name`,
  `runtime_inventory_path/sha256`, `seed_plan_path/sha256`, and
  `input_contract_label: input_repaired` fields. `artifact_root` is a dedicated
  subtree of the runtime/state artifact root; `worktree` is the imported checkout.
- `n32-production-protocol-v1`: exact rows/limits/worker contract/deadline,
  complete-triple futility, and all30/N32>=5/matched-controls promotion prerequisites.
- `n32-budget-authority-v1`: actual approved root authority, hash-bound
  `approval_basis`, amendment, finite caps, start/weekly/coordinator windows,
  and original-byte prefixes of the attempt and GPU-health ledgers (optional
  reservation-ledger prefix too). Prefix entries are `{bytes, sha256}` keyed by
  ledger filename. A prefix may be extended but never rewritten.
- `n32-root-production-review-v1` and `n32-execution-release-v1`: bind the exact
  plan reference, source/runtime/protocol/authority, limits and phase permissions.
  The release contains `root_review`; review contains `decision: APPROVED`.
  Exact field contracts are in the validator, not inferred from emitted traces.

The state must already carry `n32_budget_authority` equal to the plan's hash
reference and matching adopted caps/amendment/private resource isolation. The
adapter never installs these fields. The weekly effective ceiling reuses N31's
existing `effective_hours`; all episode and health aggregation, reservation
checks, integer timeout admission, and state synchronization reuse generic
runner functions. The original generic dispatch routes retain their prior
behavior through extracted shared helpers. N31 scientific files are unchanged.

## Process and identity contract

Every attempt ID equals its episode key. Random-suffix IDs are rejected. Null
`retry_of` and `recovery_of` match the generic non-retry journal schema; every
non-null value, including an empty string, is forbidden. Outputs and worker
artifacts cannot be overwritten. All30 external manifests are checked before
dispatch, using the actual committed source and generic runtime inventory,
checkpoint, seed/init-row/BDDL and task-cache gates. Loaded module backing bytes
and origins are checked. No expectation comes from an emitted trace.

The adapter acquires only `data/qd-ed-runner.lock` and `data/qd-ed-state.lock`.
It revalidates journal prefixes, authority, source, runtime, complete valid prior
outcomes, idle GPU7 UUID, the existing hash-bound accounted CUDA/EGL proof, provider policy, private/global/bucket/protected/weekly
capacity and full1840s time allowance. It reserves and dispatches one cell using
the generic durable journal/state writer. The parent persists PID/boot/start
identity before opening the child's stdin gate. The child checks that parent
record against its actual PID/boot/start and context/release before Main. It runs Main and both
required audits in the same process. Parent terminal validation retains the
existing generic outcome/cost/provider/video gates and the native receipt gates.

A live/unknown/unsettled ledger or N32 output handle blocks further dispatch.
Valid existing outcomes and their matching terminal artifacts are reverified
and never rerun; a missing or malformed terminal artifact stops the cohort. Reconciliation never
restores a process handle from a PID or signals a preexisting process. STOP and
coordinator/deadline checks apply before dispatch; they do not terminate a live
child. Monitoring queries share the1800s timer. Loss of exclusivity telemetry
stays INVALID even if the worker later exits0. Exact-child cleanup occurs only
when that lifecycle timer expires, with10s TERM and30s KILL wait bounds. Cleanup
uses the same directly owned Popen child, verifies durable identity and parent
PID, and never signals process groups. All observed process/cleanup time remains
charged. An interrupted or unkillable/live process remains unsettled for root
reconciliation, blocking admission; the adapter cannot recover charges after a
parent crash and never guesses them to be zero.

Only complete valid triples can trigger numeric futility. Unrun cells remain
Unknown. `qd_ed_n32_report.summary` computes the prospective necessary Dev gate;
validation/formal/ablations remain closed even if that gate is met. HTTP counters
remain Unknown. Terminal failures use `success: null`, `task_failure: false`,
`outcome_valid: false`, no retry, and retained measured cost.

## Evidence and remaining prerequisites

Tests use temporary synthetic state/journals/root documents and mocked hardware,
provider and Main boundaries. The retained N32 suite exercises the real synthetic
recorder and generic/native audit receipt paths. Production lifecycle tests
exercise actual lock files, journal/state synchronization, context and process
artifacts, with a fake worker. A separate real CPU child checks exact owned-child
cleanup. No production entrypoint was invoked on owning state.

Root still must review and supply real approved protocol/authority/review/release,
freeze/adopt source and runtime/checkpoints/task inputs, reconcile actual journals
under the normal locks, adopt the actual private budget, and admit idle GPU7.
CPU fixtures do not establish GPU/device behavior, physical success, real provider
usage, or worst-case720-step audit latency. The first authorized execution must
retain the full bounded timeout, mandatory evidence and invalid-stop rules.

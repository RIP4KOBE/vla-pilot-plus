# N30 CPU science implementation

`executed_progress_continuation_mode` defaults to the quoted YAML string `off`. The isolated N30 profile adds only `executed_progress_continuation_v1` to the frozen observed Q0 profile. No runner/admission/native auditor is supplied by this phase.

Main obtains the context from the already returned observation and the existing keypoint read. Passive tracker identity is requested when N30 is enabled regardless of whether decision recording is enabled; this does not query another pose. The context preserves the original keypoint snapshot (including NumPy float64 precision), rather than reconstructing it from the provider's later native-dtype input. Stage, episode/reset generation, provider semantic identity, target index and tracker instance/generation/status bind one chunk.

The policy saves the selected native `(1,64,128)` winner before its original native-mask/FP32 execution return. Its normal full FP32 representation must match `native_plan.float()` bytewise. The unchanged converter extracts xyz/rotation indices39:45 and gripper10; raw gripper<0 maps to−1, and zero maps to+1. Main commits the exact eight decoded actions after its existing postprocessor. Each acknowledgment binds the committed action and one-based execution index to the zero-based global step, and requires a finite already returned EEF position. All eight are required. Terminal/truncated flags invalidate history as safety/reset inputs, not progress/quality signals. Missing and contradictory evidence has explicit invalid status; unrecognized providers, no approach and ordinary identity changes are inactive.

At the immediate next guided chunk, CPU float64 computes `||start-target_old||₂` and `||end-target_old||₂` using the recorded old snapshot. Only strict decrease admits continuation. It is not a grasp, object-motion, success or causal reliability label. Only one completed chunk is retained. Current target coordinates continue to control ordinary scoring.

After the original fresh generation, copy row15 as `cat(previous_native[0,8:64], fresh[15,56:64])`. Rows0..14 remain exact fresh rows. Apply the original action mask at the original site. No new model, denoise, provider evaluation, RNG, projection or environment query is added. The proposal competes in the unchanged Q0 archive/ED/selection; it is not forced to survive or execute. Existing warm_start_mix/N3 paths remain off.

The auxiliary `initial_final` trace has a necessary N30-active association change: it denotes the composed canonical initial population and reuses that population's own score. Discarded fresh-row scores are never relabeled. A separate passive N30 event retains the complete unscored fresh native population, prior selected plan/hash, fresh tail, inserted row, action mask, current context and explicit trace semantics. Default-off and inactive paths retain the original trace. Other auxiliary stages/calls remain unchanged. With frozen Main pretest enabled: canonical176/11, total256/16,19RBF,21forwards×16rows per guided chunk. With pretest disabled only canonical176/11 scores occur. Five single-row forwards remain for unguided chunks. Whole-episode work can vary with guidance and length.

N30 scalar telemetry is present only for the opt-in mode; legacy metric JSON omits the new field. Events are bounded by one native selected plan per guided decision, one prior/fresh population on an active replacement, and at most eight actual acknowledgments per completed prefix. Tensor evidence is not placed in metric JSON. Instrumentation does not decide eligibility or alter RNG.

The focused synthetic tests execute real RDTSteer select/guided/decoder/commit/ack methods with the existing fake DiT/scheduler/adapter and AST-load only the new Main callback functions. They do not import/run the full Main application or a simulator. A pinned d855 source-only fixture supplies the three changed computational/control methods for numeric default-off comparison; unchanged methods use the current byte-identical implementation. FP32/BF16 byte comparisons, RNG/counters, both pretest modes, recorder on/off, actual Hydra composition, invalid/missing/reset/identity conditions and original-snapshot precision are covered. This is CPU source/wiring evidence, not actual GPU, task success or physical validation.

Future integration still requires profile-bound independent copy/feedback native audit, complete same-process receipts, current source/runtime/provider/budget admission and the separately reviewed three-arm screen controller. No online release or new authority is created here.

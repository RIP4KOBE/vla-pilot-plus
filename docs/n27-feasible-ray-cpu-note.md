# N27 feasible-ray update: pure CPU preparation

Base: `6026794cd5d52f3a5054bf2704ebb3c516f9f47e`. This phase adds only `core/qd_feasible_ray_update.py`, its standalone synthetic tests, and this note. No policy, configuration, native auditor, controller, plan or runtime route is changed. Absolute task score is **Unknown / not evaluated**.

The helper accepts matching finite strided FP32/BF16 `(16,8,3)` tensors: original model-output prefix `b` and the existing native proposed operand `d`. It returns a new native-dtype prefix and FP32 `(16,)` alpha. Nonzero `d` requires strictly interior `b`; boundaries/exterior are rejected, even if the proposed direction points inward. Zero coordinates preserve the original `b` bytes, including signed zero and already-exterior values. Inputs, strides, storage offsets, gradient flags and RNG remain unchanged. No model Jacobian is constructed.

Each particle's alpha is `min(1, all directional ratios)` computed from `b.float()` and `d.float()` using FP32 operations. Positive `d` uses `(1-b)/d`, negative uses `(-1-b)/d`; zeros impose no bound. Legitimate positive-infinite ratios from tiny finite updates are nonbinding. All-zero particles yield alpha1. The FP32 candidate is `b+alpha*d`; only moving coordinates retain its box-corrected/cast result. The final select preserves native zero-coordinate bytes. Alpha is maximal under this specified FP32 ratio calculation, not an exact-real maximal-step claim. Correction and rounding can alter exact ray collinearity; this is explicit, not an implementation tolerance.

The tests use an independently written scalar particle/coordinate reference with explicit FP32 rounding through `struct`, hand-set feasible/limited examples, and bounded mathematical properties. Coverage includes both dtypes; 16-particle contiguous, transpose and model-like `(16,67,128)` backing-slice layouts; all-zero/one-active-row, mixed signs, near-boundaries, largest/tiny finite updates; zero-coordinate signed/exterior values; alpha1 native-add byte parity on moving coordinates; aliasing inputs, no autograd/RNG effects; malformed type/shape/dtype/layout/device, nonfinite input and strict-support rejection. A separate finite synthetic grid supplies a demonstrable FP32 raw-candidate overshoot that the stated final correction removes. It is arithmetic coverage, not experimental-data selection.

The initial 33 tests and one additional rounding-correction test passed, with no guard denials or failed runs, in cumulative 2.1773985631 seconds including Torch startup (limit180 seconds). CPU affinity and Torch intra/inter-op threads were2; CUDA hidden/uninitialized. The guard blocks actual artifacts, other experiment code, network/process/model/simulator calls. The only `/proc` exception is Torch's normal own-process maps read during dependency loading. Exact run commands and immutable source/log hashes are in the external phase report and manifest under this N27 variant. No CUDA arithmetic equivalence is inferred from these CPU checks.

# main.py — Deep Analysis

## Overview

`main.py` is the top-level entry point for **VLA-Pilot++**, a Vision-Language-Action (VLA) steering framework. It orchestrates robot policy inference with real-time guidance generated by large language/vision models (LLMs/VLMs). The system supports multiple simulation and real-world backends (CALVIN, LIBERO, RealWorld) and two policy types (Diffusion Policy, π0.5).

---

## High-Level Architecture

```
main.py
├── Hydra config loading (@hydra.main decorator)
├── Main class
│   ├── __init__()         — wires all subsystems
│   ├── _init_components() — perception & VLM modules
│   ├── run()              — episode loop
│   ├── _run_episode()     — single episode execution
│   ├── perform_task_for_episode() — keypoint + guidance setup
│   ├── _update_stage()    — real-time stage recognition
│   └── _get_policy_observation() — observation preprocessing
└── main() entry point (Hydra-decorated)
```

## Startup Sequence

### 1. Environment Setup (module level, before class)
- Loads `[redacted env file]` file via `python-dotenv` for secrets (e.g., API keys).
- Sets `TOKENIZERS_PARALLELISM=false` to prevent fork-safety warnings from HuggingFace tokenizers.
- **Monkey-patches** `calvin_env.scene.objects.light` with a local `patches/light.py` version that adds `initial_state` config support. This is injected into `sys.modules` before CALVIN imports run.
- Adds `PROJECT_ROOT` to `sys.path` so local modules (e.g., `steer_utils`, `utils`) resolve correctly.

### 2. `Main.__init__(cfg)` — Initialization
Receives a Hydra `DictConfig` and proceeds in this order:

| Step | What happens |
|------|-------------|
| Seed | `np.random.seed`, `torch.manual_seed`, `torch.cuda.manual_seed` |
| Backend selection | Reads `cfg.backend.backend` (e.g., `"calvin"`) |
| Adapter creation | `create_adapter(backend, env_config)` — returns a `BaseEnvAdapter` |
| Task info + guide scale | Queries adapter for task instruction and optional `recommended_guide_scale`; falls back to `cfg.main.vls_config.guide_scale` (default `80.0`) |
| Policy loading | Conditionally loads `DiffusionPolicySteer` or `PI05PolicySteer` from pretrained checkpoint |
| Pre/post processors | `make_pre_post_processors()` for observation normalization and action denormalization |
| `policy.post_init()` | Binds adapter, postprocessor, batch size, and policy-specific config |
| Output directory | Created from `cfg.main.output_dir` (default `"results/"`) |
| Component init | `_init_components(cfg)` — see below |
| Policy reset | `self.policy.reset()` |

## Episode Preparation (`perform_task_for_episode`)

Runs once per episode before execution begins:

```
1. adapter.get_keypoint_detection_inputs()
   → rgb, depth, 3-D point cloud, segmentation mask, id-to-name map

2. Segmentation resolution (priority order):
   a. Adapter-provided segmentation (e.g., ground-truth CALVIN masks)
   b. Gemini grounding  → bounding-box detections → segmentation mask
   c. SAM3 text-prompted segmentation (VLM plans which objects to segment)
   d. RuntimeError if none available

3. KeypointDetector.get_keypoints()
   → 3-D keypoints per object segment + projected 2-D image

4. KeypointTracker.register_keypoints()
   → Maps keypoint IDs to object names

5. VLMAgent.generate_guidance() (or load from cache)
   → Generates staged Python guidance functions (.txt) + metadata.json
   → Functions describe geometric constraints per task stage

6. Load guidance functions per stage into self.guidance_fns dict
```

### Guidance Functions
- Stored as `.txt` files per stage (`stage1_guidance.txt`, etc.)
- Loaded via `utils.guidance_utils.load_functions_from_txt`
- Each function encodes a reward/cost over keypoint positions
- `metadata.json` records `num_stages` and stage descriptions
- Can be cached with `cfg.main.cached_functions_dir` to skip VLM generation

## Main Execution Loop (`run` + `_run_episode`)

### Outer Loop (`run`)
- Iterates `episode_num` episodes (default: 10).
- Each episode gets a random seed via `torch.randint`.
- On preparation failure: writes `error.txt`, places a `_fail_error.txt` marker, continues.
- After all episodes: computes success rate and appends to `results.txt`.

### Inner Loop (`_run_episode`)
The core step-by-step control loop:

```
while not done:
  1. generate_new_chunk = (action_executed == 0)

  2. If generate_new_chunk and guidance enabled:
     a. Get current keypoint positions from tracker
     b. _update_stage() — may query Gemini for stage transition
     c. Resolve current_guidance_fns from self.guidance_fns[current_stage]

  3. policy.select_action(observation, guidance params...)
     → Returns action_chunk of shape [batch, horizon, action_dim]

  4. Optional env_postprocessor (adapter-specific action transform)

  5. Render image with status overlay (step, stage, guidance on/off,
     gripper state, normalized reward, sigmoid strength, scale)

  6. adapter.step(action_chunk[0][action_executed])
     → obs, reward, terminated, truncated, info

  7. action_executed++; wrap at action_horizon
  8. _get_policy_observation() → preprocessed observation
  9. global_steps++

  10. On terminated/truncated:
      - Save video as success/fail
      - Increment success_count if info['success']
      - Break
```

**Action chunking**: The policy produces `action_horizon` actions at once. `action_executed` tracks which index within the chunk is being applied. When the chunk is exhausted (`action_executed == action_horizon`), it resets to 0 and a new chunk is generated next step.

## Stage Recognition System (`_update_stage`)

This is the key real-time adaptation mechanism. It detects task phase transitions and decides when to apply guidance.

### Trigger Conditions (checked every new chunk, in priority order)
1. **Gripper just closed** — `gripper_val > 0` after being `< 0`
2. **Gripper just opened** — `gripper_val < 0` after being `> 0`
3. **Reward rose above upper threshold** — Schmitt trigger rising edge (`schmitt_upper`, default `0.8`)
4. **Reward dropped below lower threshold** — Schmitt trigger falling edge (`schmitt_lower`, default `0.6`)

### On Trigger
- Calls `gemini_stage_recognizer.identify_stage_and_guidance()` with:
  - Current RGB image
  - Task instruction + stage descriptions
  - Initial keypoint-annotated image (as reference)
  - Keypoint ID → object name map
- Returns `(new_stage, need_guidance)`.
- If stage changed: calls `policy.reset_stage()` and resets reward to 0.
- Rate-limited by `vlm_query_limit` (default: 10 queries/episode).

### State Dict
```python
stage_state = {
    'prev_norm_reward': float,    # last normalized policy reward
    'prev_gripper_open': bool,    # last gripper state
    'current_stage': int,         # active task stage (1-indexed)
    'use_guidance': bool,         # whether guidance is applied
    'vlm_query_count': int,       # number of VLM queries used
}
```

## Policy Interaction

### Guidance Parameters Passed to `policy.select_action`

| Parameter | Config key | Default | Description |
|-----------|-----------|---------|-------------|
| `guide_scale` | `guide_scale` | `80.0` | Scale factor for guidance gradient |
| `sigmoid_k` | `sigmoid_k` | `12.0` | Sigmoid steepness for reward-based scale dampening |
| `sigmoid_x0` | `sigmoid_x0` | `0.7` | Sigmoid inflection point (normalized reward) |
| `start_ratio` | `start_ratio` | `None` | Fraction of diffusion steps to skip before guidance |
| `use_diversity` | `use_diversity` | `True` | Whether to add diversity noise across samples |
| `diversity_scale` | `diversity_scale` | `10.0` | Magnitude of diversity perturbation |
| `MCMC_steps` | `MCMC_steps` | `4` | Number of MCMC refinement steps |
| `use_fkd` | `use_fkd` | `False` | Enable forward-KL divergence guidance |
| `fkd_config` | `fkd` | `{}` | Config block for FKD if enabled |

### Policy Types
- **`DiffusionPolicySteer`** (`core.diffusion_policy_steer`): Diffusion-based action generation with gradient guidance injected during denoising.
- **`PI05PolicySteer`** (`core.pi05_steer`): π0.5 policy variant with similar guidance interface.

Both inherit from a common interface and are loaded via `.from_pretrained(path)`.

## Observation Pipeline

```
adapter.get_policy_observation(sample_num)
  → raw observation dict (RGB images, robot state, etc.)

policy_preprocessor(observation)
  → normalized/resized tensors in policy-expected format

→ passed to policy.select_action()
```

`sample_num` (`sample_batch_size`, default 20) controls how many parallel samples the policy generates during diffusion — more samples allow better guidance optimization.

## Debug / Test Utilities

### `run_test()`
Standalone method to validate the perception pipeline without running policy:
- Resets environment, captures RGB-D.
- Saves raw `rgb_static.png` and color-coded `segmentation.png`.
- Runs `keypoint_detector.get_keypoints_with_visualization()` (extended version with DINO visualizations).
- Saves `keypoints_projected.png` and logs per-keypoint object assignments.

### Debug Overlays (controlled by config flags)
- `debug_draw_trajectory` — draws projected action trajectory on VLM image.
- `debug_draw_keypoints` — draws tracked keypoints on each frame.

## Key Design Decisions

1. **Backend abstraction via `BaseEnvAdapter`** — all environment-specific logic is isolated, allowing the same `Main` class to work with CALVIN, LIBERO, or real robots.

2. **Guidance as staged Python functions** — VLM generates executable code describing geometric rewards; this makes the steering signal interpretable and debuggable.

3. **Schmitt trigger + gripper events for stage transitions** — avoids chattering on noisy reward signals; gripper state is a strong proxy for task phase boundaries.

4. **Action chunking** — diffusion policies output multi-step action sequences; the system replans at chunk boundaries, not every step, reducing latency.

5. **VLM query rate limiting** — `vlm_query_limit` prevents excessive Gemini API calls per episode while still allowing dynamic adaptation.

6. **CALVIN light patch** — injected via `sys.modules` before any CALVIN import, avoiding upstream source modification.

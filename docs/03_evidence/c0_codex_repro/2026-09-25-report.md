## 固定条件与变化

历史源码基于 `53187e6ea8b69e9f830c10be0bc25757db5d2794`，只叠加共同的 Codex Stage 传输适配和失败即停逻辑；当前源码基于 `77761b4cda78ac3b6762a6aa60f97b07fde7c1dc`。两组共用同一适配器字节、Stage 模板、历史缓存文件、模型 `gpt-6-astra`/low、180 秒调用时限、50 次查询上限和零步最小查询间隔。调用要求完整 JSON schema 回复；Stage 错误不计科学失败。

原始 C0 命令直接来自保留的 `job_manifest.json`，两组保留 `libero_object_swap`、task 0–9 顺序、严格扰动、种子 0、episode seeds `[44,235,43,546,6,621,197,87,151,548]`、720 步、RDT Object EMA、EDS population 16/10 轮、非 CEM、温度 0.1、3→1 renoise、absolute EEF RBF diversity 配置、Stage ON、grounding OFF、QD archive OFF。仅调整输出目录、物理 GPU2/EGL 设备，以及上述共同 Stage 接入；当前源码新增 QD 选项明确关闭。

运行前对两组 Hydra job 配置逐字段检查：`policy` 和 `backend` 相等；历史 C0 已有的 `main.eds_config` 键和值全部相等。差别为各自输出目录、当前源码显式的零步 Stage 查询间隔和四个关闭/固定的新版 QD 键。共享 checkpoint、编码器路径由相同的 `policy` 配置指定。

运行中的 task 0 初始证据也匹配：首个动作块的 `keypoints_3d.json` 和 `single_step_particles.csv` 在两组中分别逐字节相同；`first_chunk_metadata.json` 的共同科学字段相同，差异仅是耗时字段和当前源码新增的关闭状态 QD 诊断字段。这检验了首块初始状态和 EDS 粒子生成，不能代替全回合一致性证明。

task 0 完成后进一步核对：两组均在 720 步失败；11 次 Stage 查询的步数、提示词与图像哈希、解析后的阶段/guidance 决策逐次相同。该 task 的 6 条 EDS 指标记录中，所有共同科学字段相同；非科学差异为输出路径、耗时字段和当前源码新增的 QD 诊断字段。

task 1 两组也均在 720 步失败，10 次 Stage 输入指纹与控制决策逐次相同。task 2 两组同为 720 步失败，但发生首次可定位的在线模型非确定性：前 14 次查询的步数、提示词和图像指纹完全相同；第 408 步（第 14 次）对同一输入，历史源码组获 guidance ON，当前源码组获 OFF，随后 Stage 事件数分别为 20 和 14。这一处输入相同而决策不同不能解释为源码造成的差异，也使其后续轨迹失去严格配对条件。

到 task 3，首块关键点文件仍相同，但粒子 CSV 已不同，首次 Stage 输入也不同；task 3–9 的首块粒子 CSV 均不匹配。`main.py` 只在启动时设置全局 Torch/NumPy 随机种子，逐 episode 的固定 seeds 用于环境 reset，未逐 episode 重置全局 Torch 随机流；此前 task 2 的分叉很可能改变后续随机数消耗。因此后续任务的轨迹差异不能直接作为源码回归的因果证据。

本机两组共用 Python 3.12.12、PyTorch 2.7.1+cu126、NumPy 2.2.6、MuJoCo 3.7.0、diffusers 0.35.2、H200 GPU2。旧仓库依赖清单包含 PyTorch cu118、NumPy 1.26.4、MuJoCo 3.4.0。连同 Stage 服务及 GPU5→GPU2 的变化，旧环境未原样恢复。

## 决策

**旧环境未严格恢复。** 旧源码在可达的 Codex 条件下只得到 1/10，而非旧 Gemini/Poe 条件下的 3/10；Stage 供应方、软件依赖版本和 GPU 都已变化。历史源码组的 task 9 成功说明仿真、权重加载、RDT+EDS 与 Stage 至少能完成一项任务，不能把其余失败归为“程序根本没运行”。但它也不能证明旧 3/10 的执行环境已还原。

**当前源码是否有 C0 回归，证据不足以定论。** 当前组为 0/10，比历史源码组少 task 9 一项成功；这个数值差异真实存在。与此同时，两组 task 0、1 的 Stage 输入、决策和结果逐次一致，task 0 的 EDS 共同科学指标也一致；task 2 第 408 步出现同输入而 Codex 决策不同，之后任务共享的全局随机流分叉。task 9 开始时粒子和图像已经不同。因此 1/10 对 0/10 的结果不能被解释为已证实的源码退化，也不能证明当前源码完全无回归。十任务各一次的样本量同样不足以稳定估计成功率。

**暂不建议恢复新 QD/ED 算法优化。** 目前的当前源码 C0 是 0/10，旧 3/10 未恢复，且在线 Stage 对同一输入能给出不同控制决策。下一步若仍要检验旧 3/10，须恢复原 Gemini/Poe 接入与旧依赖环境，按原 GPU/输入条件再跑；Poe 当前不可用，这一严格复现路径暂时不能执行。若转而以 Codex 为新实验条件，应先把 Stage 回复按提示词和图像指纹冻结/回放，并将每个 task 的全局随机流隔离，再在这个**新协议**下复核旧/当前 C0；这会是新的诊断实验，不应改写本次或旧实验结果。完成稳定基线及源码差异定位后，才能合理评估新 QD 机制的收益。

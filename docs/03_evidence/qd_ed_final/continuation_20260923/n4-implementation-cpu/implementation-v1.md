# N4 terminal-population consumer implementation

N4 is implemented and CPU tested; no online score exists. The only algorithm switch is `qd_final_selection_mode=terminal_population_v1`, with default `archive_global_best`. The candidate accepts only the frozen Q0 combination, rejects N2/N3, non-Q0 archive options and active initial/ED cache use, and requires eight-action chunks.

`TerminalPopulation.capture` preserves the last actually scored, masked native sixteen and same-call original costs/rewards before archive consumption. Execution uses its first native cost minimum, preserving all ties and occurrence/source IDs when the observer is present. Cell and immediate parent-cell metadata reuse already computed values; they do not identify unique archive insertion ancestry. Archive search, updates, sparse parent supply and global-best diagnostics remain intact. The existing archive hard-gate check is performed before switching execution domains.

The actual selected raw provider scalar goes through the original Stage normalization function. Its spread reference stays the old FP32 archive cost vector. `terminal_population_stage_binding` passively records the fields immediately after that function returns; it is not a recording of the later Stage API input. No reward, projection, model, Stage or decoder call is added. The old final archive target-distance diagnostic uses exactly its old pool and winner, lives under `qd_archive_reference`, and N4's selected `target_distance_after` is explicitly unknown (`None`).

The focused suite passed 40 checks in 17.35 seconds. Two of those tests were then extended to finish the invented collector action lifecycle and re-passed in 5.99 seconds; these are overlapping checks. Both FP32/BF16 real CPU stub-search → deployed `select_action` decode → collector outputs passed the independently implemented N4 auditor, each with 11 canonical batches, 176 candidates, ten parent rounds, eight actual synthetic dispatches and no errors. The fixture reference comparison happened to differ; it is implementation evidence, not N4 experimental activity or task performance. Exact source hashes, commands and integration references are in `implementation-v1.json`.

Default C0/Q0 JSON omits all three new metric fields. Existing N2/N3 behavior is unchanged. CPU tests compare RNG, all provider/model counters and projection row sequences across Q0/N4 and verify `_last_scale` with an archive whose spread differs from the terminal pool. The source was changed only in this isolated branch. The root must review/integrate the separate auditor and runner, freeze source and resolve admission before any GPU run.

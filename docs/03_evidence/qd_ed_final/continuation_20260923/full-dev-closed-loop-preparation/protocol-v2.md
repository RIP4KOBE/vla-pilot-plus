# Operational protocol v2 — optional Stage association correction

This note amends only the optional-field association semantics in operational protocol-v1. Both original drafts and the v1 evidence remain unchanged. No actual full-Dev chronology was read to make this correction; independent source/synthetic review found the two defects before actual-read authorization.

- A Stage `global_step` is usable for temporal joining only when it is a nonnegative integer (not a boolean). Missing/null, negative, string or floating-point locations remain in the event stream with `location_status=Unknown_missing_or_invalid_step`. They undergo no predecessor subtraction or current-decision association. No event is dropped and query-status counts still describe the recorded events.
- Compare after-state only when there is one known same-step decision, both stage values are nonnegative integers, and both guidance values are booleans. Missing/null/untyped after-state yields `same_step_context_agrees=null` and `state_comparison_status=Unknown_location_decision_or_state`. Only fully known values can produce `known_match/true` or `known_mismatch/false`. A missing after-state does not erase an independently known same-step sent-gripper association.

These are Unknown semantics, not extra task-validity, query-quality or admission gates. A complete valid episode can retain unknown optional chronology. Absent Stage files, present-empty streams, known matches/mismatches, every event, exact sent-gripper comparisons, actual action coverage, reset/interval conventions and all scientific exclusions retain their previous meaning.

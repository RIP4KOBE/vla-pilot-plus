# Full N2 Dev closed-loop chronology — protocol draft v1

Status: documentation preparation only, 2026-09-23. This draft neither authorizes a data read nor implements a reader. Execution requires the original 30-cell Dev matrix to have one accepted, condition-valid representative per cell, followed by root review of the exact scope and a separate hash-bound read authorization. A passing success-rate threshold is **not** a prerequisite for describing a complete Dev matrix. This analysis adds no acceptance or promotion criterion and cannot change the running candidate, recovery policy, frozen source, or protected-phase allocation.

This is prospective for this reviewer's unread task1–9 chronology, **after exposure to task0 exploratory findings**. It is not preregistration before all Dev outcomes or before task0 results. Task0 findings-v3 is already-exposed motivation: it distinguishes first cutoff from subsequent reactivation and identifies a recorded first-versus-last gripper-command association. Neither observation establishes a failure mechanism. Task1–9 episode artifacts and chronology were not read to prepare this draft; no claim is made that the broader study is outcome-blind.

## Bounded question and authority

Describe when each arm actually used guidance, what structured Stage events coincided with changes, which commands had actually been sent, and how the observed EEF/finger coordinates evolved across those intervals. Apply the same fields to all tasks and arms, including successes, failures, episodes with no switching, and short terminal prefixes. Do not seek only repetitions of the task0 pattern.

A valid success may end before 720 actions and inside an eight-action chunk. Never assume 90 decisions, eight executed actions per decision, or a common realized horizon across arms. Coverage denominators are each episode's recorded executed actions and each motion interval's recorded eligible edges; no padding to 720. Preserve the frozen unsupported-provider/Q0 fallback and its already-reported reason. This description requires neither Q8 applicability on every task nor an additional numerical or activation threshold.

The frozen matrix reporter remains the sole outcome/cost reporting authority (`summarize_matrix.py` SHA `8299647ed0ec904e230058a96a8d0b2d2714e2a3879341ea6917416093c3dfe2`). It already reports valid representatives, original/recovery attempts and costs, finite-action audit evidence, canonical compute counts, Stage failures, N2 applicability and raw/internal scalar diagnostics. The chronology will reference that report and preserve its outcome fields; it will not recompute success rates, paired gains, acceptance, budgets or quality scores. A chronology integrity failure means this descriptive analysis is incomplete, not that a previously valid task outcome becomes an execution error or deserves a retry.

## Timing, intervals and uniform inclusion

Step `s` identifies the zero-based action actually sent at `s`; a fresh decision or Stage event at `s` precedes that action and follows at most `s` earlier actions. Match Stage and decisions using full episode identity plus global step; `chunk_id` is retained as provenance, not equated to collector decision ordinal. The recorded decision state is after Stage update and the missing-provider disabling branch. Keep a disagreeing/nonunique Stage association unresolved; do not overwrite actual guidance from parsed reply fields.

Group maximal contiguous executed runs by recorded `(stage, use_guidance, provider identity, reset_sequence)`; provider identity uses existing original-code/source/path/ordinal metadata without reading or invoking provider code. Wrapper-only hash variation is not semantic switching. Missing identity limits interpretation and is explicitly flagged; no source text or new target semantics are loaded. Keep decision IDs and every actual prefix, including zero-action decisions as zero coverage and no motion summary if encountered. Do not bridge a gap, terminal/truncation, or reset sequence. Environment reset and recorded stage/provider changes are distinct; a stage change is not evidence of an environment reset or an independently observed controller-reset call.

All ON/OFF transitions are between contiguous decisions in the same episode/reset segment. A reset starts a new segment, not an inferred ON/OFF event. Retain all structured events, including those with no state change or no unique decision/predecessor. Query association at step zero or after an incomplete/missing predecessor is Unknown. First/last sent-command comparisons use the immediately preceding **executed** decision prefix ending at `s-1`; exact recorded numeric equality introduces no tolerance. Preserve logged policy first/last values separately: adapter mapping or dtype differences cannot be silently corrected into agreement.

For each full contiguous episode/reset segment and each state run, reuse the old reader's descriptive motion arithmetic without introducing another geometry score. Also describe the suffix after the first ON→OFF when present, applying this to every cell rather than only N2/task0. EEF starts at the preceding contiguous post-action observation when available and nonterminal; otherwise it starts at the segment's first post-action observation, explicitly omitting the unobserved first-action displacement. Store `origin_step`, first/last executed steps, origin reason and included edge count. Never substitute an automatic-reset observation or reconstruct initial EEF from a candidate projection. With a gap, report separated components and no cross-gap net displacement.

Finger qpos endpoints/ranges use the run's **first/last post-action** measurements, not EEF's optional preceding origin. Command sign changes count only consecutive commands within that run; a boundary flip is available from full commands but excluded from this count. Store these separate origin/step conventions explicitly. Missing or incompatible qpos/qvel dimensions produce Unknown affected summaries while preserving available records. Preserve each stored tensor's native dtype/shape and source sequence. JSON/Python-float descriptive arithmetic does not upgrade BF16/FP32 source precision to FP64 measurement precision.

Outputs contain every authorized cell in frozen order, every decision, actual action, structured event, state run and transition. No success/failure selection, minimum-duration filter, hand-picked “interesting” interval, or new quality ranking. A 30-row overview indexes complete per-cell chronology and descriptive counts; all task0–9 tables remain available even when the task0 pattern is absent. No group significance test, new causal classification, outcome prediction or scientific promotion decision is produced. Matched initial seeds do not make later states, equal-step actions or different arms' queries counterfactual pairs.

Policy-visible keypoint arrays are not needed for this narrower question and will not be summarized/exported. Existing N2 quality records remain references to the matrix report; do not equate changed scalars with changed actions or aggregate Q8 magnitudes against controls.

Actual normalized Stage inputs, physical grasp/release/contact, target progress, object attachment/fallback, correctness of a Stage reply, unique archive ancestry and unexecuted outcomes stay Unknown. Chronology can identify a source-backed interface question for a **future** separately specified Dev intervention; it cannot modify N2, retroactively select evidence, establish a mechanism or supply future feedback to online choice. No protected evaluation is allocated by this draft.

Freeze a new reader/protocol/source manifest only after review and synthetic boundary tests; root's later authorization binds those hashes, the complete authoritative matrix report and the exact 30 representatives.

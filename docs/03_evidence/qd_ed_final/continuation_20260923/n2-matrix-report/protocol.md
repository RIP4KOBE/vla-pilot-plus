# N2 matrix report v1 — prospective reporting contract

Prepared during the first C0 cell, before this tool reads any new cohort outcome, audit or runtime artifact. Only static frozen protocol, runner, auditor, public telemetry declarations and their assignments were inspected. The tool is stdlib-only and never loads tensor bundles, Torch, policy/providers/projectors or a simulator. No W source or running condition is changed.

The base matrix is exactly the frozen plan SHA `ec037ec84555bd46d3b776f29979545d21b21c1f3671c3bd32b07e933d5cdc45`: Dev tasks0–9, C0/Q0/N2 in that order, matching env/policy seeds and init within each task. This tool cannot pool old observations, other worktrees, task5 invalid historical records, validation or formal data. A later explicit plan revision may only preserve the original 30 scientific cells and source/runtime identity and add the protocol's bounded recoveries. Every terminal must bind a listed plan, GPU3, the exact scientific/source/runtime/profile/init identity and N2 cohort certificate.

Manifest entries name immutable `{path,sha256}` references. Invalid terminals are read alone, with original event/outcome/failure reason/cost retained; even `event=valid` is invalid when `outcome_valid=false`. No invalid row reads metric/audit/bundle data to restore the frozen condition. A condition-valid terminal without an accepted complete audit is `pending_or_rejected_audit` and preserves the raw task outcome outside scientific counts. Accepted audit paths, episode and compute linkage are checked before explicit metric/compute JSONL reads. The frozen auditor's accepted result supplies action-finiteness/linkage evidence; this summarizer does not rerun it or read tensors. Its SHA-bound report is a provenance assertion, not independent revalidation of the audit internals.

Each scientific cell contributes at most one accepted valid outcome. A valid result cannot be superseded; one explicitly linked infrastructure recovery may resolve an invalid original cell, while both attempts and both costs remain. Missing/invalid cells never become failures or a reduced denominator. All30 accepted valid cells are required before overall paired gained/lost tasks or success deltas are computed. A complete result also displays the existing numeric criterion (N2>=5/10 and >=each control); this is not promotion or dispatch authorization. First-three completion is reported separately without releasing the existing correctness/activation checkpoint.

Cost totals distinguish complete observed sums from partial observed subtotals and Unknown. They include all supplied episode terminals, including invalid/recovered attempts. HTTP requests/retries through Codex remain Unknown; optional reasoning-token absence is not zero. Missing telemetry never becomes a zero-call claim. Report per-arm full-episode model/denoise/reward/encoder/DINO/Stage counters, latency, GPU process cost, canonical11/176 counts, Stage failures, finite-action audit evidence and observer overhead. Cost inventory completeness is a root manifest assertion; this tool does not scan live attempts or claim a global ledger/health-resource total. Reused health costs are not charged again.

For accepted N2 cells report exact recorded applicability reasons/target identity, canonical raw/internal scalar counts, changed scalar counts and selected-raw-minus-final-best-raw gap. Validate these counts against the actual recorded arrays without recomputing either quality formula. Do not equate changed scalar values with changed selected actions or substantive search activity. Inapplicable chunks retain their fallback reason and absent raw gap; no raw value is synthesized. Actual normalized Stage input is not logged: the available separation evidence is source/CPU tests plus recorded selected raw scalar, explicitly not a directly observed normalized input. The existing checkpoint reviewer remains responsible for substantive activation and raw-Stage correctness.

No new threshold, scoring rule, target rule, formula, tie rule, candidate selection or causal criterion is introduced. Geometry, physical benefit and counterfactual success are outside this compact report.

## Input and execution

Schema `qd-ed-n2-report-input-v1`: `script_sha256`, `protocol_sha256`, `authorization` reference, `base_plan` reference, optional `plan_revisions` references, `input_scope_complete` boolean and `attempts` list. An attempt has `terminal` only when invalid/pending audit, `terminal,audit` when audit pending/rejected, or `terminal,audit,compute,metrics` when valid and accepted. Paths must be the standard files under the terminal's own output directory; no glob or automatic waiting is implemented.

Root's separate authorization binds `script={path,sha256}`, `protocol_sha256` and `base_plan_sha256`. It is written after helper review/freeze and before actual reads. Use `CUDA_VISIBLE_DEVICES='' PYTHONDONTWRITEBYTECODE=1 .../python summarize_matrix.py --manifest ... --output <new-json> --execute-reviewed`. The report includes the exact input manifest and its SHA. New output only; no W/state/ledger/previous report writes.

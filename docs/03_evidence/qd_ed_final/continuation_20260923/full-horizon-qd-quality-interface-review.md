# Full-horizon QD quality: frozen-source interface review

Reviewed source: `/home/hynx/VLA-Pilot++/.worktrees/exp/rdt-qd-ed-final-20260921T093925Z` (W), HEAD `0d59b853a241cd88d984f5126428720a14abbfd5`. All line references below refer to that revision. This is an interface review, not an algorithm proposal or an authorization to run an experiment. No weights, thresholds, new quality formula, retention rule, or target resolver have been selected. Review used source reads only: no GPU, model, provider, simulator, or episode analysis; the fourth invalid observation bundle was not read. No W files were changed.

The existing canonical score call already computes the complete projected execution prefix, including t8. A prospective internal QD quality can therefore use that projection without another model, provider, or projection call. This is feasible only after making three currently missing contracts explicit: carrying the canonical geometry through score results and retained archive entries; separating internal ranking quality from original provider reward; and establishing a conservative, function-bound target interpretation before search. Replacing the existing `rewards`/`costs` tensor in place is not a contained QD change because that tensor also reaches Stage triggering.

**Geometry and execution contract.** `_decode_rdt_actions_for_guidance` and `_rdt_sample_to_trajectory_3d` (`core/rdt_policy_steer.py:6967`, `:6974`) decode the first H actions and obtain H+1 positions. For H=8 the shape is `(B,9,3)`, representing t0 through t8. `_trajectory_reward_slice(..., "eds")` (`:1730`) uses `[:,1:H,:3]`, so the provider still receives exactly t1 through t7. The t8 position is available before candidate selection even though it is outside the provider input. Extending the provider slice, re-calling the provider with t8, changing the eight-action chunk, or changing the postprocessor is outside the requested interface scope.

The projection is a kinematic proxy. `LiberoEnvAdapter.delta_actions_to_ee_trajectory` (`core/env_adapters/libero_adapter.py:1627`) reads the current EEF position, casts it to the action dtype, and cumulatively adds translation commands at the existing `0.01` scale. It performs no simulation step and does not predict contacts, object motion, tracking error, or grasp state. With the production dtype, later conversion to float32 cannot recover precision already lost at the origin/action/keypoint casts. `_rdt_sample_to_trajectory_3d` also has an adapter-missing zero fallback; that must not qualify as meaningful geometry for an enabled quality rule. Any future use must preserve the distinction between projected commands and actual postprocessed float32/binary-gripper commands sent by `core/env_adapters/libero_adapter.py:1695`.

`_score_particles` computes the full projection at `core/rdt_policy_steer.py:1752`, passes the unchanged slice to each provider, then stores the detached aggregate in the sample dtype. The observer records full and sliced projections, but the observer is write-only; reading saved evidence inside policy would introduce a new dependency and is not the reuse route. A call-local score payload is the appropriate existing interface to extend. The canonical initial call is at `:4859`; canonical offspring scoring returns through `_eds_rollout_reference` (`:3391`) and the baseline/RBF score-info paths (`:3464`, `:3774`). Transport must preserve batch order and distinguish the initial call, each offspring call, and auxiliary trace/scoring calls. A mutable global “last projection” is insufficient: repeated/auxiliary calls can overwrite it. Action fingerprint alone also cannot establish the original occurrence when identical actions appear more than once.

The current Q0 path has no elite carryover, so the offspring score results are reused rather than rescaled through an added population score call (`core/rdt_policy_steer.py:5805`). Initial and offspring archive admissions occur at `:4922` and `:5843`. Any retained geometry, raw reward, and target contract must survive replacement, parent allocation, final cell ordering, and any supported rebin operation. The final archive extraction at `:6485` currently reconstructs `population_info={"rewards": population_rewards}` and drops any other score payload. Extending only the score return dictionary would therefore be incomplete.

**Actual computation cost.** Reusing `full_trajs` at the canonical scoring boundary adds no projection call, but arithmetic, storage, validation, and any host/device transfer still have cost. If that tensor is not retained, projecting the final archive is an additional projector batch with K adapter calls for K retained elites. This does not add a provider/model call, but it is not free. Reconstructing geometry from the final 16 offspring also cannot describe older retained elites.

There are already other projections: `_eds_qd_descriptor` (`core/rdt_policy_steer.py:4676`) independently projects the population; the shadow candidate stream calls it at `:4891`, and archive descriptor construction also calls it. Trace trajectory generation (`:4640`) and `_eds_target_distance` (`:4155`) project again. Diversity/gradient paths have their own projection use. This review does not propose deduplicating those existing paths or changing their numerical/gradient behavior. It specifically identifies the canonical scoring projection as an available input to a new internal calculation.

The existing hard gates at `core/rdt_policy_steer.py:6686` require 16 × (10+1) = 176 canonical candidate evaluations, 11 score calls, and 176 QD admissions per full guided Q0 chunk. `configs/qd_ed_final/baseline_profiles.json:1120` separately fixes eight executed actions and distinguishes candidate evaluations from diffusion forward calls. The counters at `core/rdt_policy_steer.py:1393` do not count projection invocations. A future parity claim must separately verify projection calls/rows, original provider calls, model/RBF/scheduler calls, wall time, and memory; 176/11 alone cannot prove unchanged computation. No warm start, extra rollout, provider probe, or rescore is needed merely to transport the already available fields.

**Separate internal quality from original provider reward.** `QDArchiveEntry` (`core/qd_ed.py:300`) has one `reward`, one `cost`, a 2D descriptor, an action and provenance fields. Per-cell replacement (`:375`, `:468`) maximizes reward with a fingerprint tie-break. `select_global_best` (`:533`) maximizes that same reward. Parent allocation passes the stored rewards and costs back into the search (`core/rdt_policy_steer.py:5182`). Metrics, trace output, invariant checks, and final selection assume the same meaning. A new quality therefore needs an explicit independent channel and declared consumers; blindly changing the shared tensors can alter more than archive replacement and final ranking. Raw provider values and their existing effective aggregate must remain available without another provider evaluation.

There is a direct external side effect: final selection calls `_eds_update_guidance_metadata_from_cost(population_scores[best_idx], population_scores)` at `core/rdt_policy_steer.py:6883`. That method negates the chosen cost, sets `_last_raw_reward` and the initial Stage reward, updates normalized reward, and sets the reward spread. `_normalized_reward_from_value` (`:7202`) applies the existing normalization. `main.py:1295` reads this value and applies reward rising/falling triggers before querying Stage. Feeding a new full-horizon scalar through this route changes the units and behavior of those triggers, even with identical LLM prompts and unchanged Stage code.

For the requested internal scope, Stage must receive the original provider aggregate corresponding to the action actually selected, in the existing dtype/reward-mode and normalization contract. In normal Q0 mode this is the canonical provider aggregate already computed on t1..t7. Its raw population vector must also remain available for the existing spread metadata. Native provider returns, existing aggregated/effective reward, new internal quality, and their costs should not be mislabeled as one another in evidence. Using a higher precision raw return in place of the existing cast aggregate would itself change this contract. Selecting a different action can legitimately change its raw reward and later Stage trajectory; isolation prevents injecting new score units, not a promise that Stage calls remain numerically identical after changed actions.

The final pool contains only retained archive elites (`core/rdt_policy_steer.py:6485`). A final-only ranking cannot recover actions previously rejected from that archive. Retaining additional actions would be a separate retention change, with its own identity/storage/selection contract. Conversely, changing archive quality changes which parents and elites remain available. Neither interface permits claiming that a different final preference always preserves the old raw maximum. Any future opt-in invariant must state the new quality it governs while preserving separate raw selected/best/gap records; default-off behavior must retain the old invariant and exact tie rule. This report chooses neither a retention change nor a final preference.

**Target semantics must be established from the actual provider.** The decision already has the current keypoint tensor and callable list (`main.py:1659`, `:1681`, `:1730`; policy tensor construction at `core/rdt_policy_steer.py:1685`). The loader attaches `_guidance_original_func`, `_guidance_source_text`, and `_guidance_source_path`. The text is the loader-transformed text, not necessarily the raw file bytes: replacements occur in `utils/guidance_utils.py:73` before definition loading. `core/decision_evidence.py:47` records wrapper code, original code, and transformed-text identities without calling providers or reopening files. The shared wrapper hash alone does not establish an objective. Source path can establish provenance but must not select an algorithm by task or cache path.

The available heuristics do not meet this requirement. `_eds_infer_scoring_keypoint_indices` (`core/rdt_policy_steer.py:4559`) searches regexes across source text and defaults to `[0]`; it cannot distinguish used target expressions from comments, dead assignments, other functions in the same source, repulsion, or mixed objectives. `_eds_target_distance` (`:4155`) always chooses keypoint 0 and the last *scored* point t7. `qd_descriptor` (`core/qd_ed.py:51`) uses keypoint 0 for the t8 XY descriptor. None supplies a generic reward target. The task-cache identity check (`main.py:122`) checks task-bound keypoint wiring, not the meaning of the current provider. Stage number, task ID, seed, success, object names, file path, and a source-hash allowlist are not acceptable substitutes for semantic recognition.

A conservative function-bound recognizer is possible in principle but does not exist in the frozen implementation. One feasible interface is a bounded static interpretation of an explicitly supported source-expression subset: prove which function is the actual original callable; bind the transformed source and loader behavior to that callable; establish a unique in-bounds keypoint index from the expression (including nonzero indices); and establish the objective's direction and trajectory dependence. A literal target index alone is insufficient: a negative distance objective, repulsive reward, constant reward, and multi-term objective have different meanings. Recognition must account for permitted aliases and static weights, and reject unsupported branches, dynamic indices, closures/global dependencies, arbitrary helper calls, ambiguous multiple providers, or mutable/unverifiable bindings. It must not execute the function, rerun loader validation, or issue a provider/LLM call to discover its meaning. The loader's optional dummy-input validation (`utils/guidance_utils.py:119`) does call providers and is not such a recognizer.

An alternative future interface is explicit loader-attached semantic metadata validated against the actual original function/source, with known limitations. Such metadata is currently absent; ordinary cache metadata or an unverified label is not enough. Either route must handle the already documented compile/exec marshal-identity caveat rather than treating a wrapper hash or a filename-sensitive static hash as a semantic proof. Hashes support provenance and cache invalidation, not task-specific activation. This report does not design that resolver or certify arbitrary Python source semantics.

Unknown or unsupported semantics must use original Q0. The safe interface point is before a guided search can alter its archive/parents, so the chunk uses one coherent quality contract. Applying a different fallback per candidate can mix incomparable quality units. Discovering a problem after changed parents were already rolled out cannot recover the original Q0 trajectory without extra work; an implementation must not silently rerun and claim unchanged 176/11. This is a pre-search eligibility and failure-handling gap to resolve in any next protocol, not permission for retries. Unguided chunks retain their original path.

Before any opt-in implementation could be admitted, the bounded regression obligations are:

1. **Default-off and unknown-provider identity:** original Q0 actions, archive/final fingerprints, parent allocation, RNG consumption and original call counts remain unchanged. No geometry work or semantic loader/provider execution is added to the default-off path. Unknown semantics preserve Q0 before search branches diverge.
2. **Canonical transport:** initial plus ten offspring payloads remain paired with the correct action occurrence through replacements and sorted final extraction; auxiliary calls and duplicate fingerprints cannot supply a stale projection/raw reward. Provider inputs remain exactly t1..t7 and execution remains eight actions.
3. **Separate reward consumers:** archive/internal rank and new metrics have explicit meanings; original raw reward for the actual selected action still drives the old Stage normalization. Tests should demonstrate no new scalar leaks into `_last_raw_reward`, Stage thresholds, or original provider records. Do not assert old-raw optimality for an enabled changed ranking.
4. **Conservative semantics:** supported equivalent expressions and nonzero target indices are handled without task/seed/path/outcome branches; constants, misleading comments/dead code, dynamic/ambiguous targets, unsupported objective directions, missing metadata, and source drift remain Unknown. No resolver probe calls are allowed.
5. **Budget and evidence:** 176/11, original model/provider/RBF/scheduler counts and action duration remain checked; projection calls/rows and new memory/wall costs are reported separately. New quality evidence must preserve canonical identity and existing raw field meanings. Existing archive/loop tests provide relevant scaffolding (`tests/test_qd_ed_archive.py:214`, `:438`; `tests/test_rdt_steer.py:2271`, `:6306`, `:6682`), but none currently proves an unimplemented quality interface.

These are requirements for a later reviewed change. This report adds no configuration option, code path, test result, algorithmic effectiveness claim, or experimental dispatch.

# Continual VLA RL / RL²-VLA 恢复记录

2026-09-11，两个任务在构造新的 MuJoCo 场景时触发了共享适配器的 `LIBERO environment initialization exceeded 120s`，进程退出。检查时服务器 I/O pressure 的 full avg60 约为 25.8%，CPU pressure 很低；同一出错场景随后分别用约 11 秒和 7 秒成功建立。现有证据指向瞬时资源加载延迟，不能仅凭日志确定所有延迟都由 I/O 引起。

## 修复范围

- 只在这两个 RL baseline 的创建场景和恢复初始状态期间，设置 600 秒的外层初始化期限。共享适配器会保留已有外层期限。结束初始化后清除本次计时器，已有调用者的计时器保持有效。
- 训练配置 JSON 不变：π0.5 v44、20 个环境/位置扰动任务、batch 4 × accumulation 8、每阶段训练预算、RL²-VLA 原论文训练参数、720 步仿真 horizon 和 5 步初始等待均保持原设置。
- 不改变 native success、物理参数、扰动资源、初始状态或随机种子。没有编辑主实验的 `main.py`、`core/`、`patches/` 或规划器配置。
- 新增 Continual RL 每个采样组结束时的原子检查点，包含 LoRA、优化器、学习率调度器、采样组计数、累计步数和随机状态。初始化进入第一组前也保存一次。
- 调度器显式恢复时，会选取当前失败任务的完整 collection 前缀或优化器检查点。校验配置、基础模型、协议和任务一致；不将中断回合计为成功/失败结果。

## 验证与记录

服务器运行 `baseline/tests`：67 项通过。其中 GRPO 故障恢复测试比较中断恢复与连续训练的参数、调度器及训练步数，结果一致；计时器测试验证超时有效且正确恢复外层计时器。

两个原先出错的任务/初始状态均通过实际环境检查：PRO 资源摘要和 context 匹配，720 步 horizon 保持一致，恢复后计数 5，再执行一步物理动作后计数为 6。这些检查不纳入实验数据或成功率。

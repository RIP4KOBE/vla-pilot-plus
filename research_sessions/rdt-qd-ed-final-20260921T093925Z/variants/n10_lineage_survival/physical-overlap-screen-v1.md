# Exploratory physical-coordinate tabu reach screen

The original N7 Dev run has four same-stage immediately following guided
opportunities after ≥1 cm target-keypoint motion. Replaying its SHA-verified
native descriptors, a prior selected endpoint's *quadrant plus signed height
within 3 cm* matches only **4 of 64** next initial candidates, by transition
0/16, 1/16, 2/16, 1/16. The JSON result SHA-256 is
`cd6b9f541f1e90d2e892f4389ac6a9f71eb3cee52e40b33f2cd51f9b4109ff45`.

This 3 cm band is an exploratory CPU screen, not a preregistered threshold or
a task-success estimate. It covers initial proposals, not all later archive
parents; the original bundles also lack native tracking-validity flags.
Together with the prior numeric-cell check (four nominal parent slots of 64),
it gives **weak support for a one-chunk tabu policy** even when cell identity
is replaced by a physical descriptor. A future feedback candidate should
change a broader, task-relevant mechanism only after E2 tracking passes its
predeclared gate; this screen alone cannot select or promote one.

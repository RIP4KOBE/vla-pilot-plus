Input roles and bounds

The inventory schema is `n27-terminal-metadata-input-v1`, with `root_authorized=true`, `executable=true`, `refs`, `attempts`, and `files`. The delivered template has both flags false. `files` has unique absolute JSON paths and exact `{role,path,sha256,present,bytes}` entries. Present files have SHA-256 and measured bytes; an explicitly absent file has `present=false, sha256=null, bytes=0`. Every used reference is exactly `{path,sha256}` and must match its declared role. Unused inventory entries are rejected. All reads are once and cached by role/path; no transitive reference is followed unless already listed. Caps are 120 JSON files, 16 MiB per file and 128 MiB total, checked before allocation. Duplicate JSON keys, nonfinite literals, symlinks, nonregular files, drift, payload paths and duplicate physical paths fail. The inventory itself has a separate 16 MiB cap. No actual collector is included.

The 18 required control roles are `plan, source, result, status, journal, resources, precheck, cleanup, proof, proof_plan, proof_report, proof_process, proof_terminal, bridge, source_review, authority, controller, release`. There are at most 18 attempts, in original journal order. Each has `{attempt_id, refs}` with exactly `terminal, context, process, receipt, audit`; their filenames are enforced under the frozen attempt root. Each recovery additionally binds `eligibility` and `recovery_attestation`, at most two of each. Nominal maximum is 112 files. Missing per-attempt records remain missing; they cannot satisfy a valid-cell gate. The reader neither reads nor authorizes metrics, episode compute, raw Stage, tensors, images, stdout or protected outcomes.

`journal` is `n27-current-terminal-journal-projection-v1`; `resources` is `n27-current-terminal-resource-projection-v1`. Each contains the N27 cohort ID, `events`, matching `event_count`, `all_matching_events=true`, `source_ledger` and `collector` hash refs, and finite Unix `collected_at`. Journal additionally binds `snapshot` (the existing result's N27-only `ledger_snapshot`) and `snapshot_events_sha256=canonical(events)`. Root must extract ALL matching events and compare the current filtered subset under the owning locks. The original full private ledger reference is provenance, never followed and not required to remain permanently unchanged after unrelated later additions. The receipt's potentially large `evidence.files` array is only checked as a canonical metadata digest; its tensor paths are never opened.

The root prerequisite attestation is `n27-terminal-prerequisite-attestation-v1`: bindings for plan/source/proof/bridge/source_review/authority/release, runtime ref, exact source commit, `source_files_verified=345`, original operations `['validate_plan','build_command']`, successful prerequisite and historical-lineage conclusions, collector ref, zero model/API/simulator calls, and all16 command templates in plan order. Templates are the original `build_command` argv with the prospective attempt ID `__N27_REVIEW_ATTEMPT__`. The reader substitutes the actual attempt ID and independently compares the worker context, command digest, plan/profile/runtime/input identity, process, receipt and terminal. The attestation cannot override a result, cost, sequence or native-metadata inconsistency.

The controller metadata schema is `n27-root-controller-process-v1`: exact source commit, plan/release refs, physical GPU7, one_launch=true, wrapper ref, source-bound supervisor entrypoint and `{pid,proc_start_ticks,boot_id}` process. This is separate from the actual supervisor status. The cleanup attestation binds source/plan/controller/journal/resources and the exact process identities of controller, proof and EVERY attempt, including an invalid last attempt. For each known identity, root independently checks same identity and group are gone. Missing identity uses null for identity/liveness and remains Unknown. A reserved-and-aborted attempt with no dispatch need not invent a PID. A dispatched attempt with unknown historical process identity leaves `cleanup_complete=false`; root cannot use a no-matching-command scan to upgrade that to known cleanup. These root conclusions and the current-subset comparison require root's locks and collector ref, not a generic boolean. No /proc or live checks are performed by this reader.

The typed-recovery attestation is `n27-original-typed-eligibility-attestation-v1`: exact eligibility/source/plan refs, primary attempt ID, method `original_frozen_controller_and_classifier_metadata`, canonical eligibility basis hash, root verification of the original basis, collector ref, and `stage_and_tensors_reaudited_by_terminal_reader=false`.

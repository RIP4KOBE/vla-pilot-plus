# N11: quality-ranked exact parent survival within QD search

Status: preregistered implementation hypothesis; no N11 GPU release or protected-phase authorization. This is a new branch after the N7 E2 passive-tracking diagnostic stopped invalid at task 0. It does not use that invalid episode as success or tracking evidence.

Hypothesis: N7's 10-iteration QD search renoises every allocated archive parent. In the exposed original four-task Dev trace, all 5,280 parent→child fingerprints changed and only 1,009 children improved the native provider quality. Preserve up to four high-quality parents from distinct occupied QD cells as exact latents in every canonical generation, while generating and scoring the other slots as before. This may keep diverse high-quality action candidates available to the terminal grasp selector without changing the QD descriptor, Stage recognizer, or execution horizon. Prior H4 gave one global-best parent a reproduction slot but still renoised it; N11's exact non-renoised survivor lane is a different mechanism. The evidence does not establish a task-success benefit.

Algorithm: when `qd_parent_survivor_count=4`, sort the 16 allocated archive parents by descending existing same-chunk provider reward, breaking ties by QD cell then original slot. Select the highest-ranked parent from each distinct cell, up to four. Put those unchanged parent latents first in the canonical population and use the remaining allocated parents as offspring sources in their original slot order. The survivor and offspring latents are jointly rescored in one full-population canonical score call already supported by the elite path, before archive update and terminal selection. This adds at most one full-population scoring call per search iteration, but no extra diffusion or rollout generation. All 16 candidates, their parent lineage and canonical costs must be present in native evidence. If fewer than four distinct occupied cells exist, use the available distinct cells; no duplicate survivor fills. The default value remains zero with N7 byte-compatible behavior.

Only scientific change versus N7: exact survivor lane above, enabled only for the existing N7 direction-height QD profile. No change to parent-cell allocation weights, proxy reward definition, N5 terminal grasp selector, Stage prompt/model/semantic parser, guidance trigger, RDT weights, task seeds or success predicate. Frozen E2 Stage condition and GPU3 resource/budget guard remain in force. The E2 audit implementation correction is common to all arms and cannot retroactively validate its stopped diagnostic.

Before GPU dispatch: CPU tests must show no-effect parity at zero, deterministic four distinct-cell survivor selection, correct original-slot lineage and parent-cell mapping, full-population rescore with no stale offspring costs, and fail-closed config scope. Freeze one four-task matched Dev cohort on original exposed tasks 0/3/6/9, same task/seed/init row across C0/Q0/N7/N11, E2 condition and source commit. Controls are freshly rerun under that same condition. At most four C0 baseline and twelve Q0/N7/N11 development attempts, one per identity, local six-GPU-hour ceiling, no automatic retry or substitution. Stop on invalid Stage/native evidence. N11 advances only with all valid cells, ≥3/4 task successes, strictly more than same-round N7, no fewer than C0 and Q0, and a demonstrated selected-action difference in at least one guided decision. Exploratory proxy scores do not replace the success gate.

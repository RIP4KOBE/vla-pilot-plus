# Bounded immutable-source cache component — CPU preparation only

Support for active Arbor node 11.2. This is an isolated, unwired engineering component, not a new algorithm or an N26 runtime modification. The running experiment remains at 6026794. The motivation is the previously reviewed static duplication report in `../validation-cost-static-review-v1/report.md`; speedup has not been measured.

Implement a small loader-independent in-memory cache of **bytes**, using an explicit finite allowlist of repository identity, exact commit, relative path, expected SHA-256, declared size and verifier/source-bridge version. Require exact identity keys, reject mutable branch labels and path traversal, verify returned bytes on the first load, never cache failures, and expose bounded read/hit/byte counters. A trusted future adapter must provide bounded reads; this component must not claim to enforce arbitrary callback internals. Enforce declared per-object and cumulative bounds before invoking the loader, and actual size/hash bounds before admitting a value. Defaults may be no larger than 2,048 allowlisted entries, 1 MiB per object and 64 MiB total retained bytes. Keep the implementation simple; no persistence, subprocess, network, Git-history access or production imports belong in this component.

The cache must never cache an admission PASS, current working-file hash, HEAD resolution, current journal subset, missing-file assertion, process cleanup, budget, provider or GPU check. Its contract must list those live responsibilities. The component has no automatic discovery, environment fallback, execution authority or current integration. Do not modify any existing source, protocol, state, ledger, plan, checkpoint, controller or historical artifact.

Write only inside this directory, at most eight new regular files totaling 1 MiB, including this protocol. Allowed deliverables: component, focused synthetic tests, a CPU guard/harness if needed, one combined final test log, a concise contract/report and a hash manifest. Preserve any failed test log within the same cap; report a concrete cap problem instead of expanding silently. Read only this protocol and the already delivered static duplication report, plus Python/pytest standard installation files. Use synthetic byte loaders and counters; do not read real repository history or experimental records. No actual Git calls, production imports, /proc inspection, model/API/GPU/simulator, credentials or protected data. CPU threads <=2, CUDA hidden, no Torch; aggregate test execution <=120 seconds. Relevant tests should check unknown-key refusal before loader invocation, hash/size mismatch and unpoisoned retries, immutable-return behavior, identity isolation, capacity refusal before load, bounded counters and absence of a cached runtime decision.

Deliver source/manifest hashes and limitations. Root review and a separately frozen future integration with current-state checks are required before any use on real source bytes. No current experiment or later GPU dispatch is authorized by this preparation.

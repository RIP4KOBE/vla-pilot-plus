# N26 numerical interpretation questions — static only

2026-10-01. This note records source-derived questions while the frozen N26 Dev cohort is still active. It is not an N27 protocol, source modification, data-read expansion, budget adoption or execution release. No new candidate has been selected. Existing N26 numerical proofs and experimental outcomes keep their original meanings.

The current helper in `study_worktree/core/qd_actuator_clipped_rbf.py` forms native-dtype world trajectories through the existing per-row projector, then computes pairwise differences. It globally normalizes the gradient and applies the original negative scale 20. `core/qd_clean_output_rbf.py` changes the differentiation input to the same forward pass's unmodified sample prediction. Those facts support two distinct questions; neither is a demonstrated task-failure cause.

1. **Does clean-input guidance retain usable numerical separation?** For candidates with a genuinely common EEF origin, that origin cancels from pairwise trajectory distances in real arithmetic. Adding a world origin before taking differences in BF16 can round away small relative differences. This is a numerical possibility, not an observation about the actual N26 candidates. The already-prepared scalar summary can report global zero-gradient frequency and phase/task coverage, but cannot establish per-particle aliasing or prove that origin rounding caused it. If closed evidence indicates lost gradient resolution, a future separately frozen investigation could examine an origin-centred computation of the same pairwise geometry. It would need explicit origin association, permutation/translation properties, dtype/order accounting and independent native comparisons; it must not silently assume unequal origins cancel or claim CPU arithmetic reproduces CUDA. A precision change is not proof of physical progress.

2. **Does the update stay within the local regime described by the gradient?** The strict-interior clip derivative suppresses gradients outside or exactly at the bounds; it does not constrain the subsequent scale-20 update from an interior clean prediction. The nominal global operand RMS is approximately 20/sqrt(16*8*3) when the normalized gradient is supported on those components, but this is not a measured output/action displacement. A future bounded or projected update would be conceptually different from merely changing the descriptor input. It would need to distinguish the nominal operand, actual native addition, any projection and the post-scheduler action. Clipping a rounded sum and adding a rounded difference are not automatically byte-equivalent. Existing scalar summaries do not measure harmful overshoot or establish a task-linked reason to prefer such a change.

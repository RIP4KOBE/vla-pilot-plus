Recommendation: preserve the original N25 cohort as INVALID, then preregister one separate infrastructure continuation with an immutable imported prefix. Retry only the specifically named task4/N23 infrastructure-invalid primary once, then execute the original untouched suffix. Do not restart the old supervisor or broaden its timeout classifier. Abort the new continuation on any new invalid episode, including an otherwise eligible pure timeout; no further recovery or automatic resume is proposed.

This is a design, not an implementation, release, fault certification or new budget. The parent reports 18 accepted cells and six timeout failures with stream_error/item_error lifecycle records in the still-active next primary. No experiment payload was read here, so its final identity, fault set, native acceptance and settled costs remain to be established. ## Why a separate route is necessary

The indexed eight source files are the complete static read scope. In `qd_ed_n25_supervise.py:86–95`, the old launch rejects existing status/result and any prior cohort reservation. `qd_ed_n25_prepare.py:33–45` similarly forbids another freeze. Old `contract.py:225–244` requires its exact original forty-row matrix/authority; `:266–307` admits an ordered prefix only within the original cohort. Merely skipping 18 rows or changing a status flag would bypass these contracts.

`qd_ed_final_runner.py:220–221` includes iteration in episode identity. Renaming a cohort therefore does not by itself prevent accidental valid-cell duplication, and its default retry check (`:1381–1392`) cannot express a cross-cohort retry of a completed invalid primary. New admission must explicitly compare the original *scientific* identity, not mistake a new iteration/key for a new scientific cell.

Old receipt verification (`qd_ed_n23_worker.py:244–247`) calls `validate_context`; the original N25 context validator checks the old full source against current files (`contract.py:246–260`). After an administrative source integration, blindly reusing this on historical receipts would reject the old commit. Rewriting those receipts or claiming they ran the new source would be incorrect.

# N5: proximity-gated grasp-command selection

Status: prospective Dev protocol, frozen before N5 implementation or outcomes. This is one change to N4's final consumer. The four exposed Dev tasks and their prior C0/Q0/N4 results are already known; this is exploratory development, not an independent generalization test.

## Motivation and falsifiable hypothesis

N4-E1 failed its preregistered promotion gate: 1/4 successes versus C0 and Q0 at 0/4. The user-approved, GPU3-only task-9 same-state branch compared one selected eight-step prefix with the simultaneous archive reference. Neither made gripper/source contact or moved the source differently; that comparison says nothing about the other fourteen terminal candidates. Separate, already recorded N4 task-9 decision evidence shows that terminal pools at steps 16 and 24 contained positive gripper-command candidates while N4 selected negative-only chunks. At step 24, one positive-command candidate's projected EEF approach was within 0.018 m of the closest projected candidate. The later selected rollout approached its tracked keypoint while issuing negative commands. These are current-observation projection and command facts, not contact or counterfactual success.

Hypothesis: among N4's last sixteen scored offspring, prefer a candidate that commands positive gripper action while its projected EEF is close to the provider's current target, provided that candidate's approach is competitive with the best projected approach. This could improve grasp timing on the exposed task without changing QD search. It could also close too early, prefer an unrelated keypoint, or decrease success; all such failures remain in the Dev denominator.

## Single algorithm change

Start from the frozen N4-E1 transport180 implementation and profile, with Q0 archive search and parents, original provider reward and costs, fixed 16-by-10 ED schedule (176 evaluations, 11 score calls), 8-action horizon, Stage runtime and every other setting unchanged. At the last canonical iteration, retain the already computed sixteen projected EEF trajectories from the QD descriptor call. Do not run another projector, model, reward provider or simulator step. Decode the same sixteen deployed first-eight action chunks. A positive gripper command is intent only; no contact or gripper-state inference is made.

Use the existing exact provider-template recognizer solely to obtain the source-bound target-keypoint index. If the provider is unsupported, use N4's first native cost argmin for that decision and record the reason. Never silently substitute keypoint zero. For a recognized provider, calculate Euclidean distances between projected EEF positions after each of the eight actions and that target. Define `best_reach` as the smallest of all 128 distances. A candidate is eligible if **at the same timestep** it has a positive decoded gripper command and target distance at most 0.06 m and at most `best_reach + 0.03 m`. Use native first-index minimum cost among eligible candidates; if none is eligible, select N4's first native cost argmin. Ties remain first-index in the terminal population. The 0.06 m absolute and 0.03 m relative thresholds are fixed design choices from exposed task-9 geometry, not tuned against N5 outcomes. Do not use simulator contact, future observation, task success, privileged object pose, or a second provider call.

Preserve N4's separately named archive-global-best diagnostic and original archive cost spread for Stage scale. Stage receives the original raw provider reward of the actual N5 selected native action. Record all 16 native costs, decoded gripper signs, 16-by-8 projected distances, eligibility mask, target index/recognition reason, first native argmin reference, selected occurrence/cell/parent, and actual decode/dispatch identity. Fail closed on invalid finite/dtype/shape/candidate associations; unsupported provider semantics alone use the recorded N4 fallback. Independently audit the exact selection formula and original source/Stage/cost accounting before accepting an episode. N4 and default modes retain their existing behavior and tests.

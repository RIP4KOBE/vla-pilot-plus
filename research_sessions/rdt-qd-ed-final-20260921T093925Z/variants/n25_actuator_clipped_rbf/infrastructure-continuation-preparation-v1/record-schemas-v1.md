# Proposed exact record boundaries (design, all unresolved)

Every reference below is `{path, sha256}` to immutable bytes. A path is not authorization. Unknown future values stay unresolved; no record in this document is executable. Adoption must happen only after root checks the original terminal and source seal, then reviews the prospective implementation. Proposed new paths are all inside an independent N25 continuation directory; never overwrite original `result-v1.json`, authority, plan or status.

1. **`n25-named-infrastructure-failure-proof-v1`**: original cohort/source/runtime/plan refs; original root-terminal-review and result refs; Dev-only settled ledger snapshot; exact attempt_id, original scientific index18/task4/N23, terminal/process/context/receipt/native report refs; ordered failed-call identity and lifecycle-fault digest; exact machine failure set and derivative invalidities; all non-derivative gates verified; unsuccessful old-classifier verdict/source ref; full charged costs and explicit unknown usage; no later original reservations; no live owned workers. Root may certify only the specifically observed terminal fault set; no generic error allowlist or inferred absent completion. `original_outcome_valid=false` and `original_cohort_disposition=INVALID_OR_INTERRUPTED` stay literal.
2. **`n25-imported-prefix-seal-v1`**: original full source manifest/ref/commit5a; original plan/runtime/authority/release; old terminal review/result/ledger refs; original verifier source identities and root review; ordered `accepted_cells[18]` each containing original logical index/row fingerprint/attempt_id/success and terminal/context/receipt/native refs; `all_old_attempts` including invalid attempts; original native evidence digest references; counts/costs/unknown-token completeness; prefix `[0,18)` and no accepted substitute beyond it. This is the proof of prior verification, not a new execution receipt. Bind every field by seal SHA; historical provenance is never rewritten to the successor source.
3. **`n25-infrastructure-continuation-plan-v1`** (inside ordinary frozen runner plan envelope): distinct operational cohort ID; original forty-row scientific-plan ref; imported-prefix seal and named-fault proof refs; successor source and runtime; immutable mapping of all40 logical cells; exactly22 dispatchable rows `[18,40)` with only index18 retry_of original failed attempt/recovery bucket; same N25 worker audit-family contract; original profile/input refs; new protocol/authority/release refs; all protected flags false. New source requires a whole-file reverse bridge to old5a, outside-hash-bound final root review and no circular source-embedded proof hash.
4. **`n25-infrastructure-continuation-authority-v1`**: protocol, named-fault proof, prefix seal, successor plan/source/runtime/source-review/source-bridge refs; exact existing finite budget authority and caps; original local-cap authority/ref and settled spent amount; derived remaining hours; exact22 maximum new dispatches, one named exceptional retry, zero other retries, combined old+new max42/two-recovery upper ceiling and one/cell; GPU7 binding and release-time resource checks; validation/formal false; interpretation/recorded_at. A release additionally binds the final plan SHA, ordered22 keys, source SHA and this authority. The release is single-launch; any new reservation prevents another launch.
5. **`n25-infrastructure-continuation-result-v1`**: original INVALID cohort refs; successor source/plan/status/Dev-only ledger refs; prefix seal; original planned40; imported18 vs new accepted rows explicitly distinguished; first-valid ordered combined accepted vector; old/new/combined attempt and bucket denominators, costs and unknown-token completeness; every old failed attempt retained; original native counters and unchanged final gates; controller-versus-journal consistency. Disposition is computed over the logical40 and never rewrites the old disposition. Root review gets its own schema and binds this aggregate for any separately reviewed future validation or N26 predecessor addendum.

Schemas deliberately do not fill actual terminal IDs, failure lifecycle content, costs, successes or proof hashes from live state. Any discrepancy between root's final observed terminal and the proposed fault boundary blocks adoption until a concrete, newly reviewed specification resolves it. No tests or implementation accompany these designs.

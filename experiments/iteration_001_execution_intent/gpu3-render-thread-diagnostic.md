# GPU3 dedicated render thread — prospective engineering protocol

Question: does the frozen static LIBERO scene retain valid rendering across complete RDT/T5/SigLIP loading and one B1 inference when all environment and graphics-context operations occur on a separate, fixed host thread? The original scene/model probe82981d failed after model loading, before prediction. Loader subdivision741c087 failed after CUDA identity/seeding; initializing CUDA before EGL in b0c4dd moved the first failed observation to after T5 loading but did not repair rendering. These observations motivate thread isolation; they do not establish a driver or context root cause. The early-CUDA production patch remains unapplied.

One intervention relative to the original scene/model probe: the scene is constructed, initialized, rendered, closed and released on one dedicated worker thread. The caller performs the original model imports, CUDA identity/seed, load, to/eval/post_init/reset and exactly one deterministic synthetic B1 prediction. Requests are synchronous; no scene/model operations execute concurrently. Native environment/context handles remain worker-owned and never cross the request/result queue. Return only ordinary CPU scalar metadata, not exception tracebacks retaining native objects. Record actual thread identifiers for construction, initialization, every render and close, as well as model loading/prediction. Require one stable environment thread distinct from the caller.

To keep cyclic environment/context destruction within that worker, preserve the initial automatic cyclic-GC state, disable automatic collection while the worker is alive, then close the environment, release its references and explicitly collect on that worker. Preserve the original close-chain collection; the final collection is additional. Use weak references to verify release of the managed environment, simulator and rendering context. Join before restoring guards and the previous GC state, including on failure. Never perform fallback native cleanup from the caller if the worker hangs; the outer supervisor owns process termination. This is an accompanying lifetime-control change, not evidence that GC was the cause. Explicit collection can also finalize unrelated collectible objects; disclose this limitation. The process-global EGL display and registered atexit eglTerminate remain unchanged; this does not isolate process or driver state or move every global EGL operation to the worker. Do not claim general native thread safety or a production fix from a pass.

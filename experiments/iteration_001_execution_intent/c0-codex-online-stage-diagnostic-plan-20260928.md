# C0 在线 Codex Stage 诊断与统一实验条件方案（待审）

日期：2026-09-28。范围只包括 C0 在线 Stage、输入/输出协议和可重复性；不改变 RDT、ED、QD 算法，不启动 QD 候选或正式评估。本文件是排查方案，不授权 GPU episode、预算调整或结果改写。

## 已知事实与目标

- 历史 `p2_stage_on_abs_rbf_control`：在线 Poe `gemini-2.5-flash`，自由文本，10 个 Object-Swap OOD 任务中成功 3、8、9，即 3/10。
- 历史源码 + 在线 Codex CLI `gpt-6-astra`/`low`/JSON schema：1/10，成功任务 9；185 次 Stage 请求均完成。当前源码 + 相同在线 Codex 条件：0/10；173 次请求均完成。两组使用历史引导函数缓存；reward 由本地函数实时计算。
- 历史和当前源码各自回放 127 条历史 Poe 回复：均为 3/10；全部十段视频与原实验 SHA-256 相同。当前 C0 执行路径可重现，Codex 在线条件尚未达到稳定基线。
- 用户级 `~/.codex/config.toml` 的默认 `gpt-6-sol`/`xhigh` 不是实验 Stage 设置；适配器使用显式模型及推理强度并忽略用户配置。后续所有模型试验必须写入实验配置、冻结清单及原始日志。
- 最终目标是得到供 RDT+ED+QD 后续迭代共用、可审计的在线 Stage 条件；若无法在预先规定的范围内达成，明确报告未达成及推荐的替代接入。不同模型/协议即使达到 3/10，也不能称为历史 Poe 在线环境的严格同条件复现。

证据：[Codex 在线对照](../../docs/03_evidence/c0_codex_repro/2026-09-25-report.md)、[历史回复回放](../../docs/03_evidence/c0_trace_replay/2026-09-28-current-source-report.md)。

## 必须区分的原因

| 假设 | 可观察证据 | 排查方法 |
| --- | --- | --- |
| 接入、图像顺序、输出转换或解析有实现错误 | 相同输入在 Codex CLI 看到的图片/文本与预期不符，或合法回复转换后的 stage/guidance 错误 | 本地构造双图哨兵、逐字节输入快照、解析边界测试；不跑 GPU |
| Stage 模型/协议改变了控制策略 | 请求成功，但相同状态给出不同 stage/guidance；旧自由文本的解析回退不再出现 | 固定真实输入，分别测试旧格式与 JSON、推理强度和重复调用；记录原始回复 |
| 提示词与本地状态语义冲突 | “gripper closed”仅是动作命令，却暗示已抓取；reward 只是本地轨迹代价代理；旧缓存描述与任务物体不一致；提示词不含上一个 stage/guidance | 可视状态核对和一次只改一个因素的离线消融；不把旧 Poe 输出当成绝对真值 |
| 闭环随机数放大 | task 0 分叉后，其余任务虽初始关键点相同，首块策略粒子已不同 | 对照现有粒子哈希；在新比较协议中逐 episode 隔离策略 RNG，并为两组 C0 重新建基线 |

## 第一阶段：无 GPU 的实现审计与试验夹具

1. 冻结当前在线 Codex 适配器、Stage 模板、历史缓存、Hydra 配置及四组既有审计哈希。核对实际命令的 `--model`、`model_reasoning_effort`、`--output-schema`、图片附件、开发者指令及 ChatGPT 登录方式；记录 CLI 版本。不得读取或复制认证令牌。
2. 用两张内容和标签明显不同的合成 PNG 测试 `codex exec --image` 的附件顺序。当前适配器会把原本穿插在两图间的文字合并到 stdin、再传两个图片路径；检验模型是否可靠区分“初始图”和“当前图”。对 PNG 转换、颜色、尺寸、标签、JSON→旧解析器转换及 stage 0/1/2 边界分别做 CPU 测试。失败即先修实现，保留原结果。
3. 从现有事件日志汇总触发原因、原回复、解析结果、Stage 状态、reward 阈值、请求指纹和首个轨迹分叉。task 0 第 32 步及 task 2 第 408 步必须列为固定诊断例。旧结果只读。
4. 盘点可复用的精确 Stage 输入图像。现存 Codex 日志记录了 PNG 哈希，但未持久保存每次请求的 PNG 字节；视频解码帧不能冒充逐字节相同的请求图。如果无法还原精确输入，预备一次带只读观测采集的历史回复回放：十任务、127 个触发，保存初始带关键点图、当前图、完整提示词及本地状态；必须再次满足历史 127 条事件与十段视频全匹配，否则数据集无效。

第一阶段产物：输入/协议审计、可重放的 Stage 请求夹具、明确列出的实现缺陷或“未发现缺陷”证据。发现缺陷后仅修复该缺陷，先跑 CPU 测试；不同时改模型或算法。

## 第二阶段：离线 Stage 决策诊断（不用 GPU）

在各类触发、历史成功任务和失败任务中分层抽取最多 24 个精确请求。保留任务 3、8、9 作为判断是否能恢复历史成功轨迹的重要检查，不用它们单独调提示词。最多四种入围条件对同一输入各重复 3 次（最多 288 次）；随后只把最有证据支持的一个修订条件扩展到全部最多 127 个请求。离线模型调用总上限为 450 次，包含预检和扩展；额外条件须先淘汰一条入围条件，不增加上限。每次保存模型、推理强度、完整输入哈希、原文、解析状态、延迟和失败原因。

按单变量顺序比较：A 为已运行的 `gpt-6-astra`/`low`/JSON；B 只改为旧三行自由文本及旧解析器，以隔离输出格式和历史回退；C 只把推理强度改为 `medium` 或 `high`，以验证 `low` 是否不足；D 只修第一阶段证实的图片/标签顺序问题；E 在上述因素固定后，逐项澄清“夹爪命令不等于抓取成功”“reward 阈值不等于任务完成”、提供先前 stage/guidance。任务缓存身份修正必须另列为新协议，不得混进历史 C0 复现条件。

同时使用画面及诊断用仿真状态标注是否抓稳、物体是否在篮中、是否应该继续接近目标。仿真特权状态仅用来诊断标签，不能成为最终在线 Stage 的隐藏输入。报告旧 Poe 决策一致率、视觉状态错误、同输入重复决策分歧、格式/解析失败和调用成本；“与 Poe 一致”不等于“判断正确”。若某设置只是机械模仿旧解析回退而视觉决策更差，不能直接晋升。

## 第三阶段：GPU2 闭环 C0 验证，须另行冻结与授权

仅在第一、二阶段给出具体修订和 CPU 检查通过后提出 GPU 方案。建议上限 **40 个新的 C0 episode、6 GPU 小时**：如需采集精确输入，历史回复回放最多 10 个；发现实现缺陷时，单缺陷修复版最多 10 个；离线选出的一个 Stage 条件最多 10 个；通过后再用相同十任务作一次独立在线重复最多 10 个。若没有实现缺陷，跳过对应十任务，不自动挪给其他探索。沿用 GPU2、单 worker、原任务顺序/种子/权重/缓存、720 步及 C0 的全部 RDT/ED 参数，QD 始终关闭；Stage 错误或超时属于无效基础设施结果，不算任务失败。

第一个十任务在线回合保留历史连续 RNG 协议，用于检验是否在原任务设置上恢复至少 **3/10**，并单独报告任务 3、8、9 的结果。通过后必须再做独立十任务重复，检查分数与 Stage 决策稳定性；一次 3/10 不足以宣称稳定恢复。后续正式 QD 比较采用逐 episode 隔离 RNG 的**新统一协议**，并在同协议下重新跑 C0；历史 3/10 只保留为历史锚点。保存每次 Stage 的 PNG/提示词哈希、模型参数、原回复、解析值、先前状态、本地 reward 值、触发、动作块和结果，避免下一轮无法配对。

本 GPU2 study 当前有效消耗 **158/258 次、15.020869809/48 GPU 小时**，剩余未保护 episode **0 次**；验证/正式 100 次和 24 小时仍受保护。上述 40 次只是供审阅的预算提议，现有授权**不能**直接派遣任何新 GPU episode；不能从受保护额度默取。若用户批准，应先形成新的预算版本、运行清单和停机条件，再执行。

## 结论规则

- **实现问题已确认且修复有效**：有具体失败的输入/转换/解析不变量、对应修复的 CPU 证据，修复版在线 C0 至少 3/10，并在独立重复中维持；冻结这套 Codex Stage 作为后续算法比较的候选统一条件。
- **实现问题已确认但修复不充分**：保留修复和失败证据，继续区分剩余的模型决策/提示词问题；不能把“找到 bug”直接等同于“恢复基线”。
- **实现无可证缺陷，但经校准的 Codex 条件有效**：明确承认这是新的 Stage 协议，独立测得新 C0，随后在同协议下评价 QD；不宣称复现旧 Poe 的在线语义。
- **在预设搜索和预算内仍未恢复**：报告“当前测试过的 Codex 条件未达基线”，推荐恢复原 Poe/Gemini 接入以做严格历史比较，或更换/重建 Stage 机制。有限试验不能证明 Codex 模型在原则上不可修复，也不能推出只有 Poe 能有效在线工作。

无论哪条路径，都不在 C0 Stage 基线稳定前启动 QD/ED 优化或把既有 1/10、0/10 改写为有效算法增益证据。

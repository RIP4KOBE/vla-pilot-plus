# N1W 提案：只接受明确且最终完成的传输回退通知

状态：**可审阅修复已实现、CPU检查通过；新协议/额度未批准，未派发GPU**。

N1V在首个Q0/task0的第5次Stage调用上收到完整JSON及用量，但当前策略
拒绝了带有传输回退标记的error item。它没有超时，不能使用N1V仅限明确
`codex_timeout`的恢复规则。N1V保持独立已关闭版本：0有效、1无效、29未跑。

## 具体待批准变更

   C0/Q0先后次序，再执行N1。旧N1V结果不并入，不回填有效标签。
2. 三组统一使用`completed_transport_fallback_v1`。在原编号重连规则之外，
   仅允许1个`item.completed/type=error`，消息必须以CLI固定字面前缀
   `Falling back from WebSockets to HTTPS transport. `开头、有非空后缀、
   不含换行/零字符、总长<=2048。事件必须处于唯一turn内、最终消息前；
   后面必须依次出现唯一合法schema JSON消息、唯一完整usage和零退出码。
   保留原error item类型、摘要和回退分类。其他错误和不完整调用仍拒绝。
3. 保持模型、推理强度、提示词、PNG图像、180秒超时、每查询一次应用层
   调用、RDT权重、Dev种子、720步/1800秒、176候选/11批次及N1描述符不变。
   这是响应接受规则的改变，不能称为旧协议下自动合法的重试。
4. 总上限仍250尝试/48GPU小时；从recovery转1个额度给development，
   分组13/125/60/40/12。当前实际13/95/0/0/7，总115；因此可支持
   **30个新主回合+最多5个明确Stage超时恢复回合**。每task/profile最多1次；
   合法任务失败不重试。其他非可恢复无效结果、同cell二次失败、恢复耗尽
   或资源保护触发则停止；完成的有效同轮结果可在行政中断后保留。
5. 保护验证60次/14小时和正式40次/10小时。当前开发/恢复可用GPU时间

   保护而提前关闭，不承诺30个有效回合。固定GPU2、共享单worker。
6. 首2个N1只做实施检查，不按成功率筛选。N1完整10有效、>=5/10且不低于

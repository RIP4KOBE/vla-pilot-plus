## Terminal reporting

Controller and report files are confined to the exact owned variant path `RUN_DIR/validation-execution`, independently of the attempt artifact root. Attempts remain under the frozen `plan.artifact_root`; no data is moved. A symlink escape or another controller output directory is rejected before creation. Full protected detail is saved at `validation-execution/protected-detail-v1.json`; only `aggregate-disposition-v1.json` is printed. Full detail includes every planned cell, first-valid identity, all invalid/recovery attempts, paired gains/losses, 20-per-arm denominator, all observed costs and explicit partial/unknown tokens. No validation futility is added. Complete 60 cells, N24>=10/20 and >=C0/Q0, and substantive fixed QD/ED determine promotion. Positive rescue counts are descriptive, not a new veto. `cache_updates` means canonical batches whose best cache changes, not within-batch row assignment count.

If a valid journaled result is followed by a supervisor/status/postprocessing failure, the terminal writer retains it and every cost and returns INVALID. It records both controller count and journal-accepted keys; missing data remains unknown. No fabricated 0/20, silent promotion, resume or terminal overwrite. Detailed report failure preserves raw cohort events in an unadjudicated artifact plus INVALID aggregate. Aggregate output exposes no per-task/seed outcomes and does not authorize formal or declare target achieved.
